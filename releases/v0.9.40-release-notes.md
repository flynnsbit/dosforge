# dosforge v0.9.40 — Grow VHD pre-read parity + Help affordance

Both UIs (Linux TUI and Windows GUI) now show, up front, **what
can and can't be grown** — answering the user question *"do we need
a help button or some kind of pre-read control that shows the user
what can and can't grow?"*.

## What's new

### 1. Linux TUI: Grow tab now auto-reads the selected VHD

Selecting a VHD on the **Browse** tab (or typing/picking a path
in the Grow tab's *Target VHD* field) now populates the info line
with size / FAT format / cluster bytes / inferred boot mode — the
same pre-read the Windows GUI has had since v0.9.38. Previously
the Linux TUI showed a static *"Target VHD: (select via Browse tab
first)"* string that never updated.

The line also refreshes whenever you activate the Grow tab.

### 2. Growable / Not-growable verdict (both UIs)

The info line ends with an explicit verdict based on the inferred
boot mode:

* ✓ **Growable** — the source is one of FreeDOS / MS-DOS 7.10 /
  MS-DOS 6.22 / Compaq DOS 3.31.
* ✗ **Not growable — rebuild via 'dosforge create'** — the source
  is one of MS-DOS 2.x/3.3/3.31, DR-DOS 6/7, IBM PC-DOS 7.0/7.1
  SGTK / PC-DOS 2000, MS-DOS 5.0, etc.
* **?** Verdict unknown (auto-detect at grow time) — OEM string in
  the boot sector wasn't recognized; the grow backend's runtime
  detector will decide.

The verdict comes from the same `GROWABLE_BOOT_MODES` set the
backend uses, so the UI can't drift from reality.

### 3. Inline supported-modes header (both UIs)

The Grow tab now shows the supported-modes table inline as part
of the form, so a user doesn't have to dig to find out which DOS
families work:

```
Supported boot modes:
  • FreeDOS / MS-DOS 7.10  — FAT16 ≤ 2 GiB,  FAT32 ≤ 32 GiB
  • MS-DOS 6.22            — FAT16 ≤ 2 GiB
  • Compaq DOS 3.31        — FAT16 BIGDOS ≤ 504 MiB
Other boot modes must be rebuilt via 'dosforge create'.
```

### 4. **`?` Help button + modal/dialog (both UIs)**

Next to the *Grow VHD* button on both Linux TUI and Windows GUI
there's now a small *?* button. Clicking it opens a modal with the
full long-form reference:

* The four supported boot modes + each one's FS / size caps.
* Hard limits: fixed-format VHD only (no dynamic / differencing,
  no `.img` / `.ima` / `.vfd` floppies), grow-only (never shrinks),
  cluster-band must hold.
* What the grow preserves (system files / startup files /
  user dirs with mtimes).
* What's *not* supported and must be rebuilt via
  `dosforge create`.
* The 8-step pipeline reference for the curious.

* **Linux TUI**: `ModalScreen` with full-screen overlay, scrollable
  body, dismissed by Esc / Enter / Close button.
* **Windows GUI**: centered `Toplevel` modeled on v0.9.39's
  staging-DOS-path dialog (same centering + `grab_set` pattern),
  scrollable Text body, *Close* button right-aligned.

## Install

### Linux

```bash
curl -L -o /tmp/dosforge.tar.gz \
  https://github.com/flynnsbit/dosforge/releases/download/v0.9.40/dosforge-0.9.40-linux.tar.gz
tar -xzf /tmp/dosforge.tar.gz -C /tmp
cd /tmp/dosforge-0.9.40 && sudo ./install.sh
```

### Windows

Download `dosforge-0.9.40-windows-x64.zip` (full GUI) or
`dosforge-0.9.40-cli-windows-x64.zip` (CLI only), extract anywhere,
and run `dosforge.exe`.
