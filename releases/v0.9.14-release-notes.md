# dosforge v0.9.14

One more legacy DOS family floppy IMG path lands: **MS-DOS 6.0**
can now be produced as a bootable 1.44 MiB floppy via the
verbatim-Disk-1 copy path (same pattern as v0.9.13's MSDOS71 and
PCDOS2000).

## What landed

- **MSDOS6 IMG (`img-msdos6-na-1440k-sysfmt-...`)** — verbatim
  copy of `dosassets/msdos6/Microsoft MS-DOS 6.0 Plus Enhanced
  Tools (3.5).7z` Disk 1 (auto-extracted on demand via py7zr).
  Carries `IO.SYS`/`MSDOS.SYS`/`COMMAND.COM` + the MS-DOS 6.0
  utility set (`ATTRIB`, `CHKDSK`, `CHOICE`, `DEBUG`, `DEFRAG`,
  `DELTREE`, `EDIT`, `EXPAND`, `FDISK`, `FORMAT`, `HIMEM`,
  `KEYB`, `NLSFUNC`, …).  The stock `AUTOEXEC.BAT` (which ran
  `nlsfunc` → `keyb us` → `setup`) is replaced with a minimal
  `@ECHO OFF` + `PROMPT $p$g`, so the floppy boots to `A:\>`
  instead of dropping the user into the OEM setup wizard.

## Internal changes

- `src/dosforge/disk.py`
  - `verbatim_floppy_modes` extended with `BootMode.MSDOS6`
    (F1440K).  Uses the existing
    `asset_fallback_dirs=("msdos6", "dos6", "dos60")` descriptor.
  - `_sanitize_verbatim_install_floppy` membership widened from
    `{DRDOS7, MSDOS71, PCDOS2000}` to
    `{DRDOS7, MSDOS71, PCDOS2000, MSDOS6}`.  The sanitizer only
    replaces `AUTOEXEC.BAT`; OEM installer binaries
    (`SETUP.EXE`/`SETUP.MSG`/`UNINSTAL.EXE`/`SUHELPER.SYS`) stay
    on the disk so users can run them manually.
- `scripts/build-smoke-matrix.py`
  - `_IMG_UNSUPPORTED_MODES` reduced from `{MSDOS6, PCDOS, FOURDOS}`
    to `{PCDOS, FOURDOS}`.

End-to-end verification of MSDOS6 IMG build was performed via
direct `DiskManager.create_and_prepare` invocation; the produced
1,474,560-byte floppy was inspected with `mtype` / `mdir` to
confirm authentic MS-DOS 6.0 content + sanitized 26-byte
`AUTOEXEC.BAT`.

## What did not change

- VHD pipeline for MSDOS6 is byte-identical to v0.9.13.
- MSDOS6 IMG with `img_system_format=False` still goes through
  the bare-floppy code path (no boot files at all) — only the
  `--img-system-format` flag triggers the new verbatim copy.
- Generic PCDOS / 4DOS IMG paths remain unimplemented (CLI-only
  catch-all + shell-overlay code path). Future work.
