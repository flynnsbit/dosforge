# dosforge v0.9.27

## New: `dosforge inspect` subcommand

Complementary read-only primitive for downstream tooling (e.g.
`exodosconverter`) that wants to introspect a user-supplied VHD
before deciding whether to grow it, rebuild it, or leave it alone.

### What it returns

For a given VHD path, `dosforge inspect` reads:

- **VHD container**: file size, fixed-vs-dynamic, footer CHS
- **MBR**: first partition type byte, LBA start, sector count
- **BPB**: OEM stamp, FAT format (FAT12 / FAT16 / FAT32), cluster
  size, total cluster count, reserved sectors, num FATs,
  sectors-per-FAT, root dir entries, volume label, volume serial
- **Inferred boot mode**: two-stage inference
  1. Match BPB OEM stamp against known dosforge-supported modes
     (most precise -- each DOS's authentic FORMAT.COM writes a
     specific stamp like `MSDOS5.0`, `IBM  3.3`, `MSWIN4.1`,
     `FRDOS5.1`, `DRDOS  7`).
  2. When the OEM is generic (`mkfs.fat`, `MTOOLxxxx` from
     mformat), fall back to root-system-file presence:
     `KERNEL.SYS` → FreeDOS, `IO.SYS + MSDOS.SYS` on FAT32 →
     MSDOS71, `IO.SYS + MSDOS.SYS` on FAT16 → MSDOS622 family,
     `IBMBIO.COM + IBMDOS.COM` → COMPAQ331 family.
- **Root system files** present: which of `IO.SYS` / `MSDOS.SYS` /
  `IBMBIO.COM` / `IBMDOS.COM` / `KERNEL.SYS` / `COMMAND.COM` /
  `CONFIG.SYS` / `AUTOEXEC.BAT` / `FDCONFIG.SYS` / `FDAUTO.BAT`
  exist at C:\\ root (via `mdir -i <vhd>@@<off> -a ::<name>`).

### Usage

```bash
# Human-readable summary
dosforge inspect path/to/disk.vhd

# JSON for tooling
dosforge inspect path/to/disk.vhd --json
```

between invocations.

### Verified scenarios

| Disk | OEM stamp | Inferred | Notes |
|---|---|---|---|
| dosforge-built MSDOS622 32 M | `MSDOS5.0` | `msdos622` | Direct OEM match |
| dosforge-built FreeDOS 256 M FAT32 | `MTOO4049` | `freedos` | OEM unknown -> KERNEL.SYS fallback |
| dosforge-built MSDOS71 OSR2 | `MSWIN4.1` | `msdos71` | Direct OEM match |
| Compaq DOS 3.31 / DR-DOS 6 | `IBM  3.3` | `compaq331` | Direct OEM match (ambiguous between 3.31 and DR-DOS) |

### Companion to `dosforge grow`

`exodosconverter` can now:

1. Call `dosforge inspect --json` on a user-supplied VHD.
2. Read `inferred_boot_mode`, `fat_format`, `cluster_size_bytes`,
   `partition_offset_bytes` from the JSON.
3. Decide whether to call `dosforge grow` (when boot mode is in
   `GROWABLE_BOOT_MODES` and a viable larger target size exists
   within the current cluster band).
4. Build a `GrowManifest` informed by that data.

The two primitives compose without any shared state -- inspect is
pure read-only, grow consumes its own manifest.
