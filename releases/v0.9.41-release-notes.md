# dosforge v0.9.41 — Linux TUI: stop the "Grow VHD" button from wrapping

Patch release on top of v0.9.40.

## What was wrong

In v0.9.40 the new Grow tab action row reused the `.path-row`
Horizontal class, which carries a hard `Button { width: 5;
min-width: 5; max-width: 5; }` rule (intended to size the
trailing `...` browse buttons). That forced the *Grow VHD*
button into a 5-cell column, wrapping its label to two lines:

```
Gro
w
```

## What changed

- New `.actions-row` Horizontal CSS class without the
  fixed-width button rule. The Grow tab now uses it.
- New `Button.grow-help-btn` rule keeps the compact `?`
  button at width 5.
- No behavior changes — labels and handlers are untouched.

Layout verified headless via `App.run_test()`:
* `#grow-btn` renders at 14×3 ("Grow VHD" fits on one line).
* `#grow-help-btn` renders at 5×3 ("?" centered).

## Install

### Linux

```bash
curl -L -o /tmp/dosforge.tar.gz \
  https://github.com/flynnsbit/dosforge/releases/download/v0.9.41/dosforge-0.9.41-linux.tar.gz
tar -xzf /tmp/dosforge.tar.gz -C /tmp
cd /tmp/dosforge-0.9.41 && sudo ./install.sh
```

### Windows

Download `dosforge-0.9.41-windows-x64.zip` or
`dosforge-0.9.41-cli-windows-x64.zip`, extract anywhere, run
`dosforge.exe`. (Windows GUI is unaffected by this fix; the
version-lock convention ships matching artifacts anyway.)
