# dosforge v0.9.8 — FreeDOS FAT16 boot fix

Fixes a long-standing single-byte corruption in the embedded
FreeDOS FAT16 boot sector that has been silently breaking FAT16
hard-disk boot on every dosforge build whose FAT16 BPB lands a
non-trivial sectors-per-cluster value (e.g. SPC=8 on the 128 MiB
smoke-matrix VHD).

Tag: `v0.9.8` — Linux + Windows artifacts are built and uploaded
by CI in a single workflow run.

## Symptom

`vhd/vhd-freedos-fat16-na-nosysfmt-minimal-nopayload.vhd`
(128 MiB FAT16) hangs in 86Box with a blinking cursor right after
the MBR loads the partition's volume boot record. The 128 MiB
FAT32 sibling boots fine. Smaller FreeDOS FAT16 VHDs (≤32 MiB,
SPC=1) appeared to boot but only by coincidence — see Root cause.

## Root cause

The embedded `_BUILTIN_FAT16_BOOT_SECTOR_B64` in
`src/dosforge/boot.py` had a single corrupted byte at offset 171:

```
shipped dosassets/freedos/BOOTSECT_FAT16.BIN @171:  f3   (div bx)
embedded _BUILTIN_FAT16_BOOT_SECTOR_B64    @171:  f7   (div di)
```

The FreeDOS boot loader at that offset is computing FAT / root-dir
sector geometry. `div bx` divides by bytes-per-sector (the correct
divisor, loaded from the BPB earlier); `div di` divides by whatever
`DI` happens to contain at that point — which equals `BX` only when
sectors-per-cluster is 1 (small volumes). For any FAT16 volume large
enough that mkfs.fat chooses SPC ≥ 2, `DI` diverges, the divide
produces a junk sector number, and the loader either reads garbage
or wedges INT 13h.

The corruption has been in-tree since the initial check-in. It
escaped detection because:

1. The shipped `dosassets/freedos/BOOTSECT_FAT16.BIN` (used when
   `--freedos-source local` resolves to a directory) was always
   correct.
2. The buggy builtin only fires through the
   `--freedos-source auto` / image-fallback resolver path, which
   the smoke matrix started exercising at scale only in v0.9.5+.
3. Older smoke runs built small FreeDOS FAT16 VHDs (≤32 MiB, where
   SPC=1 and DI happens to equal BX), so the bad instruction was
   functionally a no-op.

## What changed

### Backend (`src/dosforge/boot.py`)

- **Regenerate `_BUILTIN_FAT16_BOOT_SECTOR_B64`** from the shipped
  `dosassets/freedos/BOOTSECT_FAT16.BIN` (1-character change in
  the base64 string). The constant now byte-equals the canonical
  in-tree FreeDOS FAT16 boot sector.
- **Reject stale on-disk caches** in
  `_load_cached_fat16_boot_record_paths`: if the cached
  `fat16-native-bootsect.bin` still has `0xf7` at offset 171 from
  a pre-v0.9.8 run, return `None` to force
  `_seed_builtin_fat16_boot_records` to overwrite it with the
  fixed bytes. Users who built FreeDOS FAT16 VHDs with v0.9.0
  through v0.9.7 will see the cache re-seed automatically on the
  next FreeDOS FAT16 build.

## How to verify

```bash
# Compare embedded constant vs shipped file
python -c "
import base64
from pathlib import Path
import dosforge.boot as b
embedded = base64.b64decode(b._BUILTIN_FAT16_BOOT_SECTOR_B64)
shipped  = Path('dosassets/freedos/BOOTSECT_FAT16.BIN').read_bytes()
print('byte[171] embedded:', f'{embedded[171]:02x}')   # f3
print('byte[171] shipped :', f'{shipped[171]:02x}')    # f3
print('byte-equal:', embedded == shipped)              # True
"

# Rebuild the failing smoke-matrix case and boot it in 86Box
sudo -v && scripts/build-smoke-matrix.py --filter 'freedos-fat16'
# Then boot vhd/vhd-freedos-fat16-na-nosysfmt-minimal-nopayload.vhd
# in 86Box with the FreeDOS profile (FIC VA-503+, Pentium MMX,
# Award BIOS, AT IDE auto).
```
