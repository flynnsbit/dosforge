# dosforge v0.8.0

Minor-version bump: TUI + GUI Step 2 (Media) controls become
hierarchical. The three competing always-visible geometry inputs
(static size, BIOS preset, custom CHS) collapse into a single
**Geometry source** picker that surfaces only the one input
relevant to your choice. Adds a live geometry preview.

## Why

The old Step 2 layout showed **Static size**, **BIOS preset**, and
**Custom CHS** side-by-side. Three competing controls with no
indication of which one wins — and the runtime precedence (custom
CHS > BIOS preset > static size) was hidden inside `disabled_fields()`.
Users could fill all three and then guess what `dosforge` would
actually use.

## What changed

### v0.8.0 Step 2 layout (TUI + GUI)

```
Disk type            [VHD ▼]
Disk controller      [Auto-detect from boot mode ▼]
Output path          [____________________________________][...]

Geometry source      [Static size (auto geometry) ▼]
  └─ Static size:    [512M___________________________]      ← only this row
                                                              shows for "size"

→ 512 MB (geometry auto-derived from size)                  ← NEW live preview

Filesystem           [FAT16 ▼]
```

```
Geometry source      [BIOS preset (Phoenix / AMI type table) ▼]
  └─ BIOS preset:    [Phoenix Type 1 — 306×4×17 — 10 MB ▼]   ← only this row
                                                              shows for "preset"

→ 10 MB (306 cyl × 4 head × 17 spt)                         ← live preview
```

```
Geometry source      [Custom CHS (cylinders, heads, sectors) ▼]
  └─ Custom CHS:     [CYL,HEAD,SPT (e.g. 306,4,17)__________]

→ 10 MB (306 cyl × 4 head × 17 spt)                         ← live preview
```

### New public API

- `dosforge.models.GeometrySource` — enum of `size` / `preset` /
  `custom_chs`.
- `dosforge.formlogic.default_state().geometry_source` — `"size"` by
  default; the snap chain auto-flips it to `"preset"` when a boot
  mode pins a BIOS Type 1 spec (COMPAQ2 / PCDOS3 / COMPAQ3).
- `dosforge.formlogic.infer_geometry_source(state)` — migrate
  pre-v0.8.0 saved states / external scripts (custom CHS wins over
  BIOS preset wins over static size).
- `dosforge.formlogic.coerce_on_geometry_source_change(state)` — clears
  the inactive geometry inputs when the user picks a different source.
- `dosforge.formlogic.geometry_preview_text(state)` — renders the
  live preview line for both UI surfaces.

### Snap behavior

`coerce_on_boot_change` now also snaps `geometry_source`:

| Boot mode | `geometry_source` | Other snaps |
|---|---|---|
| COMPAQ2 / PCDOS3 / COMPAQ3 | `preset` | bios_drive_type=phoenix:1, 10M cap |
| IBM8088 (any DOS) | `size` | 32M cap, MFM for DOS33 |
| Everything else | `size` | clears stale preset / custom CHS |

The TUI and GUI both call into `coerce_on_boot_change` so the snap
is identical across surfaces.

### Backward compatibility

- `CreateRequest` API and CLI flags (`--size`, `--bios-drive-type`,
  `--custom-chs`) are unchanged. `geometry_source` is a UI-only
  concept; the backend still computes the effective geometry from
  the same precedence chain (`custom_chs` > `bios_drive_type` >
  `size`).
- `formlogic.disabled_fields()` is now a no-op (returns `set()`).
  Kept for any external callers; the picker eliminates the need
  for the SIZE-disabled state.
- Pre-v0.8.0 saved states (FormState without `geometry_source`)
  fall through `_safe_geometry_source(state)` to `SIZE` and the
  user can re-pick if they had a preset / custom CHS set.

## Tests

176/176 focused tests pass — 10 new tests cover the
`GeometrySource` enum, `infer_geometry_source`,
`coerce_on_geometry_source_change`, the geometry-source snap in
`coerce_on_boot_change` (both early-return and default branches),
and `geometry_preview_text` for each source mode. `test_app_form.py`
(known to hang in CI per `CLAUDE.md`) was not run; the TUI
widget-ID contract is preserved (`#geometry-source` is the only
new ID).

## Deferred to a follow-up

- Tooltips on every GUI field (the original v072-gui plan item).
  Tkinter doesn't ship a native tooltip widget; needs a thin
  `tk.Toplevel`-based helper. Will land in v0.8.1 if requested.
- "▸ Advanced (MartyPC / extended AMI presets)" disclosure for the
  BIOS preset dropdown. The current 89-entry list is now hidden
  behind the geometry-source picker so it's only seen when the user
  explicitly wants a BIOS preset, which substantially reduces the
  cognitive load. Folding can come later if 89 still feels too many.
