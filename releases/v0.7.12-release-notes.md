# dosforge v0.7.12

UI cleanup — Boot OS dropdown labels in the TUI Create wizard and
the GUI Create view.

## Boot OS dropdown rewrite

The dropdown that picks which OS the produced disk boots has been
relabeled for clarity.  No backend / boot-mode behavior changes; the
underlying `BootMode` enum values are unchanged.

### Field header
`Boot mode` → `Boot OS`

Matches the existing **Step 1 — Boot OS** wizard step title, and
makes it obvious at a glance that the field selects what OS the disk
boots (not, say, BIOS boot order or chainloader mode).

### Per-option labels
- **Dropped the redundant "bootable" suffix from every option.** The
  field header now implies bootability for all non-NONE options.
- **Clarified the ambiguous `PC-DOS bootable` entry** as
  `IBM PC-DOS (user-supplied install media)`. This mode (boot-mode
  `pcdos`) is the catch-all where the user drops their own IBM
  PC-DOS install media into `dosassets/pcdos/`; the resolver falls
  back to `pcdos7` assets if `pcdos/` is empty.  The "user-supplied"
  qualifier distinguishes it from the version-specific PC-DOS modes
  (`pcdos3`, `pcdos7`, `pcdos2000`, `pcdos71`).
- **Normalized media-format tags** -- `360k MFM` (which conflated
  media format with controller type) is now `360k DSDD`.
