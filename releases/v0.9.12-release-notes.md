# dosforge v0.9.12 — DR-DOS 7 IMG: strip auto-installer wiring

Hotfix for v0.9.11. The DR-DOS 7.03 floppy IMG built fine but,
once booted in 86Box, immediately tried to run INSTALL.EXE which
hunted for a non-existent C: drive and dumped the user into
FDISK with the message:

```
Install can't find a drive C:. This may be because you have not
yet partitioned your hard disk.  The FDISK utility will now be run.
Press a key to continue...
```

Tag: `v0.9.12` — Linux + Windows artifacts are built and uploaded
by CI in a single workflow run.

## Symptom

After booting `img-drdos7-na-1440k-sysfmt-minimal-nopayload.img`
in 86Box on a no-HDD machine profile, DR-DOS 7's `IBMBIO/IBMDOS`
loaded fine, `CONFIG.SYS` ran HIMEM/SETVER/KEYB, and then the
stock `AUTOEXEC.BAT` auto-launched the OEM installer instead of
dropping the user at `A:\>`.

## Root cause

v0.9.11 added DR-DOS 7 to `verbatim_floppy_modes` (so dosforge
byte-copies `Installation & Utilities 1.img` to the output
floppy). That preserves DR-DOS's native boot sector + IBMBIO/
IBMDOS layout — which is exactly what we want — but it also
inherits the Caldera-shipped AUTOEXEC.BAT:

```
@ECHO OFF
if exist INSTALL.EXE goto install
:no_install
ECHO Insert the UTILITIES 1 disk in drive A:
pause
if not exist INSTALL.EXE goto no_install
:install
INSTALL.EXE
```

The first branch fires on every boot because the verbatim copy
still has INSTALL.EXE on disk.

DR-DOS 6's `Disk01.img` has no AUTOEXEC.BAT, and the other
verbatim profiles (COMPAQ2 / COMPAQ3 / PCDOS3) likewise boot
straight to `A:\>`, so the issue is isolated to DR-DOS 7.

## Fix

Added a post-copy sanitization step,
`DiskManager._sanitize_verbatim_install_floppy()`, that runs
only for `BootMode.DRDOS7`. It replaces the stock AUTOEXEC.BAT
with a minimal:

```
@ECHO OFF
PROMPT $p$g
```

written via `mcopy -o`. INSTALL.EXE is left on disk so the user
can run it manually with `A:\INSTALL` if they actually want to
install DR-DOS 7 to a hard disk. CONFIG.SYS is left untouched —
HIMEM.SYS/SETVER.EXE/KEYB.COM are the right things to load on a
DR-DOS 7 boot floppy.

## VHD path is unaffected

VHDs go through `_install_legacy_dos_via_qemu` which `FORMAT C:`
+ `SYS C:` + `COPY A:\COMMAND.COM C:\` — only IBMBIO.COM,
IBMDOS.COM, COMMAND.COM, and the `VHDMK.OK` marker ever land on
C:. No AUTOEXEC.BAT, no CONFIG.SYS, no INSTALL.EXE. User already
verified both DR-DOS VHDs boot to `C:\>` cleanly.

## How to verify

```bash
sudo -v && scripts/build-smoke-matrix.py --filter '^img-drdos7'

# Confirm the sanitized AUTOEXEC.BAT
mtype -i .../img-drdos7-na-1440k-sysfmt-minimal-nopayload.img \
      ::AUTOEXEC.BAT
# Expected:
#   @ECHO OFF
#   PROMPT $p$g

# Boot the floppy in 86Box (Pentium-class, A: drive, no HDD).
# Expected: reaches A:\> prompt with no installer prompt.
```
