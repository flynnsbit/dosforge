# dosforge v0.7.10

**Fourth and final fix** for the `SingleClickSelect` close-the-open-dropdown bug.

The user reported v0.7.8 still broken: clicking the up-arrow chevron of an
open Boot-mode dropdown still didn't close it.  Fixes in v0.7.5, v0.7.7,
and v0.7.8 all missed the actual event order.

## Actual root cause (verified with a headless ``Pilot`` repro)

The previous three patches assumed the click order was
``MouseDown → Click → SelectCurrent.Toggle``.  Empirical tracing shows
that on the *second* click (the close-the-open-dropdown click), the
order is actually:

```
1. SelectOverlay loses focus (the click is landing on the Select widget,
   not the overlay)
2. SelectOverlay.Dismiss(lost_focus=True) posted
3. Parent's _select_overlay_dismiss handler sets self.expanded = False
4. _watch_expanded(False) fires (CSS hides the overlay)
5. MouseDown finally delivered to our Select widget
6. our _on_mouse_down sees expanded == False, "helpfully" calls
   action_show_overlay() and re-opens the dropdown
7. SelectCurrent.Toggle arrives; our handler sees the
   "just opened on MouseDown" flag and leaves expanded = True
8. Dropdown stays open forever — the bug.
```

All three prior fixes were patching the wrong handler.  The real fix
has to live in ``_on_mouse_down``: it must recognize that the click
itself caused the blur-dismiss that just closed the overlay, and *not*
re-open it.

## The fix

`SingleClickSelect` now records a timestamp every time a
blur-driven `SelectOverlay.Dismiss(lost_focus=True)` fires.  When
`_on_mouse_down` runs, if a blur-dismiss happened within a 150 ms
grace window, it skips the re-open path entirely (the dismiss
already closed the overlay; the user wanted it closed).

* No timer or async work — just a `time.monotonic()` comparison.
* The 150 ms grace is far shorter than any realistic open-then-reopen
  click cadence, so deliberate "open-close-open" still works.
* Uses an `@on(SelectOverlay.Dismiss)` decorated handler in the
  subclass so it runs *alongside* (not in place of) the parent's
  dismiss handler — overriding by method name doesn't work because
  Textual's decorator captures the function reference at decoration
  time, bypassing MRO.

## Regression test

New `tests/test_single_click_select.py` uses Textual's `Pilot` to
simulate four sequential clicks and asserts the dropdown alternates
open / close / open / close.  This is the test that v0.7.5 / v0.7.7
/ v0.7.8 would all have failed had it existed.

## Files changed

* `src/dosforge/app.py` — `SingleClickSelect` reworked; new
  `_track_blur_dismiss` handler; `_on_mouse_down` checks the
  grace window; `_single_click_toggle` simplified.
* `tests/test_single_click_select.py` — new regression test.
* `pyproject.toml` + `src/dosforge/__init__.py` — version bump
  to 0.7.10.
