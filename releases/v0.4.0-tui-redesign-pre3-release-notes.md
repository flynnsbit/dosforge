# dosforge v0.4.0-tui-redesign-pre3 — TUI layout fixes (PRE-RELEASE)

> ⚠️ **Pre-release.** Major layout fixes on top of `pre2`. The
> `pre2` build had structural issues making the wizard unusable
> at terminal heights below ~50 rows.

## What's fixed

User reported on `pre2`:

> "borders don't look right, floppy size seems to go off the
> bottom, there is a scroll bar that does nothing on the vertical
> side, I can't seem to get to the next step after media"

### Root cause

The step container was `height: auto` and contained all ~14
controls for step 1 (media-type, machine-target, output path,
size, BIOS preset, filesystem, floppy size, etc.). When the
content was taller than the viewport, the container grew past the
bottom of the screen — pushing the wizard-nav row (Back / Next /
Quick Create) **completely off-screen**. So there was no way to
advance past step 1.

A vertical scrollbar appeared on the parent `wizard-main`, but
the parent was a `Vertical` (not a `VerticalScroll`), so clicking
the scrollbar did nothing.

The "Floppy size" label was visible at the bottom even in VHD
mode because `_sync_create_form_visibility` hid the floppy-type
`Select` but the label was a separate widget — an "orphan" label.

### Fixes

| Issue | Fix |
|---|---|
| Wizard nav off-screen | Wrapped all step containers in `VerticalScroll`. Pinned `#wizard-nav` **outside** the scroll so Back / Next / Quick Create are always visible. |
| Phantom scrollbar | The `VerticalScroll` actually scrolls now. |
| Floppy label orphan | Every toggleable `Select/Input` paired with a Label that has a matching `id`; `_sync_create_form_visibility` uses a `_toggle()` helper that hides both together. |
| Step container border stacking | Removed per-step borders. One subtle border around the whole scroll area + matching border on the summary panel — same color and style for visual consistency. |
| Summary panel height mismatch | Both the scroll area and the summary panel are now `height: 1fr`, so they fill the available space identically side-by-side. |
| Heavy vertical spacing | Label margin `0` (was `0 0 1 0`), Input/Select keep their `0 0 1 0`. Cuts step-1's vertical extent roughly in half. |
| Picker buttons inconsistent width | `btn-ghost` has explicit `min-width: 5` so the three-dot picker renders at the same width every time. |
| No focus feedback | Added `#wizard-scroll:focus-within` and `#vhd-tree:focus-within` rules — borders brighten from 50% to 100% opacity when any child has focus. |

## What's verified

Programmatic layout probe at 140×45:

| Widget | y | height | visible |
|---|---:|---:|---|
| `#wizard-progress` | 5 | 1 | ✓ |
| `#wizard-scroll` | 7 | 30 | ✓ (content scrolls) |
| `#wizard-nav` | 38 | 3 | ✓ (always pinned) |
| `#wizard-next-btn` | 38 | 3 | ✓ clickable |
| `#floppy-type-label` (VHD) | — | — | hidden (no orphan) |
| `#floppy-type-label` (IMG) | shown | — | visible |

Clicking `Next: Boot →` advances to step 2, reveals `← Back`, and
hides `Next: Boot →` on step 4.

All 28 `tests/test_app_form.py` cases still pass.

## What's NOT changed

Backend pipeline (qemu-img, mtools, DOSBox-X), boot install,
vendor binaries, dosassets — all identical to `pre2`.
