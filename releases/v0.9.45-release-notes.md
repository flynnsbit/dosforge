# dosforge v0.9.45 release notes

## Summary

Hotfix for MFM + FAT16 VHD creation when no BIOS preset is set.
Previously dosforge silently capped the disk to 10 MiB (Phoenix
Type 1) regardless of the size you typed, then immediately failed
validation with **"FAT16 images must be at least 16 MiB."** Users
trying *Boot=IBM PC 8088*, *Filesystem=FAT16*, *Static size=32M*
(or any size), *Controller=MFM* on MartyPC hit this dead-end.

v0.9.45 derives an MFM/XT-class CHS geometry from your typed size
so the requested size is honored, rounded up to the nearest
cylinder boundary.

## What changed

**`src/dosforge/disk.py` `_xt_class_geometry`**

When the user supplies neither a BIOS preset (`--bios-drive-type`)
nor an explicit `--custom-chs`, the function now:

- Iterates head counts in `(4, 6, 8, 15)` with the universal MFM
  `spt=17`.
- Picks the smallest head count that keeps cylinders ≤ 1024
  (the XT-class BIOS limit).
- Returns a geometry sized to fit (and round up to) the user's
  `request.size_bytes`.
- Raises a clear `ValidationError` when the request exceeds the
  MFM ceiling (~127 MiB = 1024 × 15 × 17 × 512), instead of
  silently shrinking — directs the user to pick a smaller size,
  switch to `--disk-controller ide`, or pass an explicit BIOS
  preset / custom CHS.

Examples (auto-derive output):

| Requested | Geometry (C × H × S) | Actual size |
|----------:|----------------------|------------:|
| 16 MiB    | 482 × 4 × 17         | 16.0 MiB    |
| 32 MiB    | 964 × 4 × 17         | 32.0 MiB    |
| 50 MiB    | 1004 × 6 × 17        | 50.0 MiB    |
| 100 MiB   | 804 × 15 × 17        | 100.1 MiB   |
| 200 MiB   | — (raises)           | "MFM ceiling ~127 MiB" |

## User-facing impact

You can now select:

- **Boot OS:** IBM PC 8088/V20 (DOS 3.3 or DOS 5.0)
- **Filesystem:** FAT16
- **Static size:** any value ≥ 16 MiB, up to the DOS-version cap
  (DOS33 = 32 MiB, DOS50 = 504 MiB) and the MFM ceiling (~127 MiB)
- **Controller:** MFM
- **BIOS preset:** *(none — auto-derive)*

…and Create succeeds. The resulting VHD's CHS geometry will match
your size, slightly rounded up to the next MFM cylinder boundary
(e.g. 32M → 32.008 MiB).

For MartyPC users specifically: pair this with
`--bios-drive-type martypc-xebec:1` if you need the canonical 10
MiB Phoenix Type 1 geometry; otherwise the auto-derive gives you
larger MFM disks that fit in the XT-class BIOS table window.

## Edge case: DOS 3.3 + 32 MiB

DOS 3.3 caps FAT16 partitions at 32 MiB (65,535 sectors). The
nearest MFM cylinder-aligned geometry to 32 MiB is 32.008 MiB,
which is 16 sectors *over* the cap. Users targeting DOS 3.3 on
MFM should pick **31M or smaller** to stay cleanly under the cap.

## Tests

New regression suite `tests/test_disk_mfm_autogeometry.py`:

- Parametrized check that auto-geometry honors user-typed sizes
  for 16, 20, 32, 50, 64, 100, and 127 MiB.
- Asserts the function picks 4-head geometry for small sizes
  and steps up to 15 heads only when forced.
- Asserts the new oversize ValidationError fires for 200 MiB.
- Asserts zero/negative `size_bytes` still falls back to Phoenix
  Type 1 (legacy compatibility).

`pytest tests/test_disk_mfm_autogeometry.py tests/test_disk_validation.py
tests/test_formlogic.py -q` → **161 passed**.
