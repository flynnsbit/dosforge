# dosforge v0.5.0-gui-pre2 — GUI rendering fixes

Pre1 had three rendering problems that made the New Disk form look broken
on Windows:

1. **Comboboxes appeared as empty grey bands** — they were never being
   given their default values.
2. **Border lines around every field** — nesting sv_ttk's `Card.TFrame`
   inside another `Card.TFrame` drew nested panel borders.
3. **Slow paint** — multiple nested frames + the panel sprite redraw on
   every visibility update.

## Fixes

- **Combo values now display reliably.** `_Combo.set_value()` calls
  `widget.set(label)` directly instead of relying only on a bound
  `StringVar` — the readonly display refreshes immediately across ttk
  implementations.
- **Field controls now render correctly.** `Field` takes a control
  *factory* (`Callable[[ttk.Frame], tk.Widget]`) so the control's actual
  parent matches its layout master. Previously controls were created
  with the card body as parent and then `grid(in_=Field._frame)` was
  used to place them — that pattern silently rendered the widgets at
  zero opacity inside our scrollable canvas.
- **Single border per card.** `Field` no longer wraps controls in a
  nested `Card.TFrame`. One outer card panel, flat content inside.
- **Stripped overlapping ttk styles.** The custom `DfCardHeading` /
  `DfFieldLabel` / `DfPanel.TFrame` styles broke sv_ttk's TLabel
  inheritance and made label backgrounds render system white. Removed
  in favour of plain `Heading.TLabel` / `FieldLabel.TLabel` / default
  TFrame, all of which sv_ttk themes correctly.
- **Reduced layout depth** for faster paint and visibility transitions.

## Visual verification

The Output and Media & geometry cards now show: focused path entry with
visible text, volume label entry, "Overwrite" checkbox + label, "Media
type" combobox displaying *VHD (fixed-size hard disk)*, "Machine target"
showing *Generic (86Box / QEMU / etc.)*, size entry showing *512M*, BIOS
preset combobox showing *Custom — use size field*, FAT16 filesystem
combo, and Boot mode showing *None (data disk only)*.

No new behaviour or backend changes — pure GUI rendering fixes.
