# dosforge v0.7.3

Two changes:

1. **New Linux one-line installer** at
   `scripts/install.sh`.  Eliminates README version-number maintenance
   and makes Linux install a single curl.
2. **README cleanup** to use the new installer and drop hardcoded
   version numbers.

## The one-line installer

```bash
curl -fsSL https://raw.githubusercontent.com/flynnsbit/dosforge/main/scripts/install.sh | bash
```

What it does:

1. Detects your distro (Debian/Ubuntu/Mint/Pop/Fedora/RHEL/Arch/openSUSE)
   and installs system tools via the native package manager (`apt`,
   `dnf`, `pacman`, `zypper`).  Will prompt for sudo.
2. Queries GitHub's
   [`/releases/latest`](https://github.com/flynnsbit/dosforge/releases/latest)
   API for the current release tag — **always grabs whatever is
   newest**.  No version pin, no hardcoding.
3. Downloads the matching `dosforge-<version>-linux.tar.gz`.
4. Creates an isolated venv under
   `~/.local/share/dosforge/<version>/venv` (multiple versions can
   coexist; a `current` symlink always points to the latest).
5. Symlinks `~/.local/bin/dosforge` so it's on `PATH` after the
   first install.  Warns if `~/.local/bin` isn't on `PATH` yet.
6. Hydrates the per-mode `~/.local/share/dosforge/dosassets/` folder
   skeleton.
7. Smoke-tests `dosforge --help` before declaring success.

### Flags

| Flag | Effect |
|---|---|
| `--no-system-deps` | Skip the package-manager call (use if you've installed qemu/mtools manually) |
| `--no-init-assets` | Skip `dosforge init-assets` |
| `--no-symlink` | Skip `~/.local/bin/dosforge` |
| `--prefix DIR` | Install root (default `~/.local/share/dosforge`) |
| `--tag v0.7.2` | Install a specific tag instead of latest |
| `--keep-tarball` | Keep the downloaded `.tar.gz` |
| `--help` | Print help |

### Review-before-run

```bash
curl -fsSL https://raw.githubusercontent.com/flynnsbit/dosforge/main/scripts/install.sh -o install-dosforge.sh
less install-dosforge.sh
bash install-dosforge.sh
```

- Removed hardcoded `linux-v0.7.1/dosforge-0.7.1-linux.tar.gz` URLs.

  (post-v0.7.2 consolidation) instead of the old separate-tag scheme,
  and points at `releases/latest` instead of a specific release-notes
