# dosforge v0.4.0-dosbox-x-pre2 — bundle bloat cleanup (PRE-RELEASE)

> ⚠️ **Pre-release.** Same DOSBox-X swap as `-pre1` plus aggressive
> bundle pruning. Still awaiting end-to-end install validation for
> legacy DOS modes.

## What's new vs `-pre1`

Stripped ~210 files / ~3 MB of verified-stale content from the
PyInstaller bundles:

- `Cryptodome/SelfTest/` (1.4 MB / 97 files) — pycryptodome's self-test
  suite, never runs at runtime
- `Cryptodome/PublicKey/` (1.1 MB / 23 files) — RSA/DSA/ECC/ElGamal;
  py7zr's 7z handling only uses symmetric AES
- `Cryptodome/Signature/` (61 KB / 13 files) — digital signature
  primitives; not used by py7zr
- All `*-*.dist-info/` directories (~300 KB / ~80 files) — pip install
  metadata, useless at runtime
- `setuptools/` (21 KB / 8 files) — leftover from pip env

## Why this is safe

py7zr → pyzstd / pyppmd / pybcj / inflate64 / brotli for 7z compression
codecs, plus pycryptodome's `Cipher.AES` + `Hash.SHA256` + `Random` +
`Util` for AES-encrypted 7z archives. None of the stripped paths are
imported by these.

CI gained regression-guard checks that fail the build if any of these
paths reappear in any variant.

## Implementation

`windows/spec_helpers.py` (new) provides three helpers used by all
three PyInstaller specs:

- `strip_bloat(datas/binaries)` — filters TOC entries by target path
- `strip_hidden_imports(modules)` — drops `Cryptodome.SelfTest.*` etc.
  from hidden-imports so PyInstaller doesn't bytecompile them
- `post_build_cleanup(dist_dir)` — final pass that removes any
  `.dist-info` directories + the four stripped subpackages that
  PyInstaller's metadata pass writes after COLLECT

Plus `EXCLUDE_MODULES` is added to each spec's `Analysis(excludes=...)`
list so PyInstaller's analyzer never considers these modules in the
first place.
