# dosforge v0.9.25

## Verification + smoke-matrix cleanup

End-to-end verification of v0.9.20–v0.9.24 across all six legacy DOS
modes that go through the QEMU `FORMAT C:` install pipeline.  All
six produce bootable VHDs with curated `C:\DOS\` payloads under the
FULL install profile on Windows:

| Mode | Format | Size | Build | C:\DOS\ files |
|---|---|---|---|---|
| `drdos6` | FAT16 | 32 M | ~21 s | 20 |
| `drdos7` | FAT16 | 32 M | ~26 s | 25 |
| `pcdos2000` | FAT16 | 32 M | ~31 s | 14 |
| `compaq2` | FAT12 | 16 M | ~13 s | 14 |
| `compaq3` | FAT12 | 16 M | ~16 s | 17 |
| `pcdos3` | FAT12 | 16 M | ~14 s | 16 |

Notable observations:

- **DR-DOS 7** payload picks up `DRMOUSE.COM` correctly (new in
  v0.9.23 whitelist), `HIMEM.SYS`, `EDIT.COM`, plus the staples.
- **PC-DOS 2000** stages the authentic `E.EXE` (PC-DOS editor) with
  its companion `E.EX`, `E.INI`, `EHELP.HLP`.
- **DOS 2.11 / 3.0** modes are tiny by design (mid-1980s utilities)
  but still get a useful end-user set.
- No installer/login/multi-user internals leak through in any mode.

### Smoke matrix `_KNOWN_BROKEN` comment refresh

`scripts/build-smoke-matrix.py` had a misleading v0.9.10-era comment
saying "DR-DOS 6/7 entries removed in v0.9.10 -- install pipeline
now uses FORMAT C: + explicit SYS C: two-step AUTOEXEC".  v0.9.10
removed the entries prematurely (the install was actually broken
until v0.9.20's `/X` fix and v0.9.21's resolver dispatch).

Replaced the stale comment with an accurate audit pointing at the
real fixes (v0.9.20 `/X`, v0.9.21 dispatch, v0.9.23 / v0.9.24
curated payloads).  The `_KNOWN_BROKEN` table itself remains empty
— all six modes now genuinely pass.
