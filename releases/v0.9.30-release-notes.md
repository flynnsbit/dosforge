# dosforge v0.9.30

## TUI + GUI integration for `inspect` and `grow` (feature parity)

The v0.9.27 `dosforge inspect` and v0.9.26 / v0.9.29 `dosforge grow`
primitives were CLI-only.  This release exposes both through the
Linux TUI (textual) and Windows GUI (tkinter) with **the same form
fields and behavior on each surface**, matching the project's
Linux-TUI / Windows-GUI default routing.

### Inspect

| Surface | How |
|---|---|
| Windows GUI | **Image Tools → "Inspect VHD"** button.  Output renders in the existing log/output area below the buttons. |
| Linux TUI | **Image Tools tab → "Inspect VHD (MBR + BPB + root system files)"** button.  Output renders in the status pane (same as `ls`). |

The rendered output mirrors `dosforge inspect <vhd>` exactly — file
size, footer CHS, partition entry, BPB OEM + FAT format + cluster
size, volume label + serial, inferred boot mode (with two-stage
fallback), and root system files present.

### Grow

| Surface | How |
|---|---|
| Windows GUI | New **"Grow Disk"** nav rail item (between *Image Tools* and *Mounts*). |
| Linux TUI | New **"Grow Disk"** tab (between *Image Tools* and *Mounts*). |

Both surfaces accept the same inputs:

- **Target VHD path** (browse button on GUI; `...` button on TUI;
  defaults to the currently-selected image in either case).
- **New size** (human-friendly: `128M`, `256M`, `1G`, `2G`).
- **Boot mode** (combo/select with the four supported modes:
  `compaq331`, `msdos622`, `msdos71`, `freedos`).
  Auto-inferred from the existing VHD via `inspect_vhd` on GUI
  when you pick a target; same auto-fill on TUI via the same path
  when the path is set before refreshing.
- **Staging sources** (zero or more `SRC=DEST` pairs: pick host
  directory + DOS destination path).  GUI uses a Listbox with
  Add directory / Remove buttons; TUI uses a single-line entry +
  Add button that appends to a running `Static`-rendered list.
- **Headless boot probe** checkbox (default on — matches CLI
  default behavior).
- **Keep backup** checkbox (default on — matches CLI default).

Pressing **Grow VHD** runs the same `dosforge.grow.grow_vhd` API the
CLI invokes, on a worker thread so the UI stays responsive during
the 7-30 second extract/rebuild/probe cycle.
