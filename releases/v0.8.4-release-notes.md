# dosforge v0.8.4

Bug fix: pre-DOS-5 boot modes (`msdos33`, `msdos331`, `pcdos3`,
`compaq2`, `compaq3`, `compaq331`, `pcdos`, `ibm8088`+DOS33) +
FULL install profile no longer hard-fail on "MS-DOS install media
is missing required startup files".

## Background

MS-DOS 3.x / IBM PC-DOS 3.x / Compaq DOS 2.x/3.x install diskettes
**never shipped CONFIG.SYS or AUTOEXEC.BAT**. Those files were
user-created during personalization. SETUP.EXE wasn't introduced
until MS-DOS 5.0.

The Phase 14B strict-authenticity rule (added in v0.6.x) was
designed for MS-DOS 5+/6+/PC-DOS 7 install media where SETUP DID
write startup files -- the rule preserves them byte-verbatim so
the produced VHD matches a real personalized install. Applying
the same rule to MS-DOS 3.x install media incorrectly treats the
absence of files Microsoft never put there as a fatal install-media
defect.

## The bug

Picking `--boot-mode msdos33` with the FULL install profile and
otherwise-valid install media in `dosassets/msdos33/` raised:

```
MS-DOS install media is missing required startup file(s):
CONFIG.SYS, AUTOEXEC.BAT.
Per the DOS authenticity rule, dosforge no longer synthesizes
CONFIG.SYS / AUTOEXEC.BAT -- provide the originals from your
install diskettes in the boot-assets directory.  As a temporary
workaround, set DOSFORGE_ALLOW_SYNTHESIZED_STARTUP=1 to restore
the previous synthesizing behavior.
```

The user followed every instruction correctly. The error was the
tool's fault for asking for files MS-DOS 3.30 never shipped.

## Fix

`BootAssetResolver._ensure_msdos_startup_files` now skips the
strict-require check when `pre_dos5=True` and falls through to the
synthesis path. The synthesis was already era-aware:

- **CONFIG.SYS** (DOS 3.x): `FILES=30\r\nBUFFERS=20\r\n`
  (the minimal subset DOS 3.x actually understands; DOS 3.x trips
  "Unrecognized command" on `DOS=HIGH`, `LASTDRIVE=Z`, etc.)
- **AUTOEXEC.BAT**: `@ECHO OFF\r\nPATH=C:\DOS\r\n`

Both are sensible 1987-era defaults that boot cleanly on real
MS-DOS 3.30 hardware.

User-supplied CONFIG.SYS / AUTOEXEC.BAT dropped into the asset dir
are still preserved (the synthesis loop's "if file already exists,
keep it" branch wins).

## Strict rule still enforced for DOS 5+

- MS-DOS 5.0, 6.0, 6.22 — still hard-fail when install media
  missing startup files (those releases DID ship them via SETUP).
- PC-DOS 7.0, 2000, 7.1 — same.
- MS-DOS 7.10 (Win95 OSR2) — same.
- DR-DOS 6.0, 7.03 — still hard-fail (DR-DOS shipped startup
  files; bypassing INSTALL.EXE doesn't change that).

The `DOSFORGE_ALLOW_SYNTHESIZED_STARTUP=1` env opt-out still works
for DOS 5+ if you want the legacy behavior for those modes too.

## Tests

191/191 focused tests pass — 2 new tests added in
`test_strict_authenticity.py`:

- `test_pre_dos5_skips_strict_require_and_synthesizes` — confirms
  pre_dos5=True bypasses the require check and writes era-correct
  CONFIG.SYS (FILES=30, BUFFERS=20, no DOS=HIGH).
- `test_pre_dos5_preserves_user_supplied_startup_files` — confirms
  user-supplied CONFIG.SYS / AUTOEXEC.BAT are preserved when
  present, not overwritten by synthesis.

## Files changed

- `src/dosforge/boot.py` — `_ensure_msdos_startup_files` strict
  branch now also checks `not pre_dos5`; expanded docstring.
- `tests/test_strict_authenticity.py` — 2 new test cases.
