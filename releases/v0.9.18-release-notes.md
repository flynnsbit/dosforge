# dosforge v0.9.18

UX: DR-DOS 6 / DR-DOS 7 VHD builds now fast-fail with a clear
"use IMG mode instead" message at the moment you click **Create**,
instead of running the QEMU install for 5 minutes and timing out
with a cryptic ``VHDMK.OK`` marker error.

## Background

The v0.9.7 smoke matrix triage classified
`(VHD, drdos6)` and `(VHD, drdos7)` as `_KNOWN_BROKEN`: the
QEMU-driven install hangs at DR-DOS's `FORMAT.COM` prompt because
the canned ``A:\\YES.TXT`` input sequence was tuned for MS-DOS /
PC-DOS prompts, and DR-DOS asks for things in a different order.
The smoke matrix knows to skip this combo; the GUI didn't, so
users selecting "DR-DOS 6.0 + VHD + Create" sat through a
300-second timeout and got:

```
Digital Research DR DOS 6.0 SYS step did not complete within 300s.
The emulated DOS run did not write C:\VHDMK.OK. This usually
means the VHD geometry, BPB, or install floppy is malformed.
```

Misleading -- the real reason is that DR-DOS's installer prompt
sequence is not yet automated.

## Fix

Added a `_KNOWN_BROKEN_VHD_BOOT_MODES` table in
`formlogic.py` keyed by `BootMode` -> remediation message.
Two gates now consult it:

1. `validate_media_step` (TUI wizard Step 2 -> Step 3 "Next"
   click) returns the remediation message instead of falling
   through to format / size validation.
2. `build_create_request` (GUI Create button + CLI submit) raises
   `DosForgeError` with the same message.

Effect: selecting **Media type = VHD** + **Boot OS = Digital
Research DR DOS 6.0** (or **Caldera DR-DOS 7.03**) in either the
TUI or GUI immediately surfaces:

> DR-DOS 6.0 VHD builds are not supported yet -- the QEMU-driven
> install hangs at FORMAT.COM's prompt.  Use Media type = IMG
> with boot mode drdos6 instead (writes a verbatim 720k Disk 1
> IMG that boots in 86Box / DOSBox-X).

The user immediately knows the supported path (IMG mode, which
landed in v0.9.11 and uses a verbatim Disk 1 copy that doesn't
need to drive the installer at all).

## What didn't change

- IMG mode for DR-DOS 6/7 still works -- v0.9.11's verbatim
  Disk 1 copy path is unaffected.
- All other VHD boot modes still build as before.
- Smoke matrix script's `_KNOWN_BROKEN` table -- still skips the
  same combos for the same reason; the gate is just user-facing
  now.

## Future work

Implementing DR-DOS 6/7 VHD support requires reverse-engineering
DR-DOS `FORMAT.COM`'s actual prompt sequence (it prompts for the
volume label first, then the destructive-format confirm, with
slightly different wording than MS-DOS), and either:

- recording a verified `YES.TXT` byte sequence for each DR-DOS
  installer, or
- switching to `INSTALL.EXE`-driven install (the GUI wizard that
  ships with DR-DOS), which is a bigger lift but matches what
  real users did in 1991 / 1999.

When that lands, remove the relevant entry from
`_KNOWN_BROKEN_VHD_BOOT_MODES` and add a `_NOT_BROKEN` test case.

## Files changed

- `src/dosforge/formlogic.py` -- new
  `_KNOWN_BROKEN_VHD_BOOT_MODES` constant; gates added in
