# dosforge v0.9.1

TUI status-bar improvements: action buttons now report what they're
doing in the status pane the moment you press them, not just after
they finish.  Long-running fetches no longer freeze the TUI.

## What changed

### `Fetch latest FreeDOS` button

Was synchronous: pressing it froze the TUI for 5-30 s with no
feedback while urllib pulled the ~5-15 MB FreeDOS image and
extracted it.

Now:

1. Status bar shows ``Downloading FreeDOS assets (this can take
   5-30 s)... from <url>`` immediately on press.
2. Animated spinner ticks with an elapsed-time readout so you can
   see the download is in progress.
3. The button greys out so you can't double-trigger.
4. Work runs on a Textual worker thread so the rest of the UI
   (Browse / Tools / Mounts tabs) stays responsive.
5. On completion: ``[OK] Downloaded and extracted FreeDOS assets
   to <path> in <N>s``.
6. On failure: ``FreeDOS fetch failed after <N>s: <error>`` so you
   know which step blew up.

### `Fetch IBM PC-DOS 7.1 assets (SGTK download)` button

Same fix: was synchronous, now runs on a worker thread with the
spinner.  Stage labels from the existing progress callback
(``locating_sevenzip`` -> ``downloading_sgtk`` -> ``extracting_sgtk``
-> ``locating_dos_files`` -> ``staging_files`` ->
``hydrating_pcdos2000`` -> ``done``) update the spinner message in
place via ``call_from_thread`` so you can watch progress without UI
freeze.

### "Starting..." status for short-running actions

These previously only showed feedback AFTER they finished, leaving
the user wondering for a beat whether the button registered:

- **Mount disk image** -> ``Mounting <image>...`` shown immediately.
- **Unmount** -> ``Unmounting <path>...``.
- **Open in file manager** -> ``Opening <path>...``.
- **List image contents** (`ls`) -> ``Reading directory listing from <image>...``.
- **Extract file** -> ``Extracting <image>:<dos-path>...``.
- **Run privilege diagnostics** -> ``Running privilege diagnostics...``.

All success messages now also prefix with ``[OK]`` so the success
vs in-progress distinction is visually obvious.

## What didn't change

- GUI (`dosforge gui`) already uses ``app.run_operation`` which
  shows ``busy_msg`` during fetches -- no change needed.
- ``Create + format VHD/IMG`` button already had the worker +
  spinner pattern (v0.4.x).
- No behaviour change: same operations succeed / fail with the
  same outcomes; only the user-facing status feedback improved.

## Tests

All 191 focused tests pass.  No new tests added (status messages
are UI behaviour that test_app_form.py would normally cover, but
that file is known to hang in this environment per CLAUDE.md).
