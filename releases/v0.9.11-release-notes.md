# dosforge v0.9.11 — DR-DOS 6 / DR-DOS 7 floppy IMG support

Brings the DR-DOS family's IMG (floppy) output path to parity
with VHD: `img-drdos6-na-360k-sysfmt-minimal-nopayload.img` and
`img-drdos7-na-1440k-sysfmt-minimal-nopayload.img` now build
authentic bootable install floppies via verbatim copy of the
DR-DOS install Disk 1 (same minimally-invasive pattern already
used for COMPAQ2, COMPAQ3, and PCDOS3).

Tag: `v0.9.11` — Linux + Windows artifacts are built and uploaded
by CI in a single workflow run.

## Symptom (v0.9.10 and earlier)

`scripts/build-smoke-matrix.py` reported the DR-DOS IMG cases
as `SKIP-not-implemented`:

```
[5/42] img-drdos6-na-1440k-sysfmt-minimal-nopayload
    ⏭️  SKIP  (IMG floppy build path is not implemented for drdos6)
[6/42] img-drdos7-na-1440k-sysfmt-minimal-nopayload
    ⏭️  SKIP  (IMG floppy build path is not implemented for drdos7)
```

End-to-end via `dosforge create --media-type img --boot-mode drdos6`
the IMG floppy branch hit `BootAssetResolver.resolve()` with no
DRDOS6/DRDOS7 dispatch arm, producing the
`ValidationError: Unsupported boot mode: drdos6` exit.

## Root cause

`BootAssetResolver` only had `_resolve_*` methods for the MS-DOS,
PC-DOS, FreeDOS, IBM 8088, and Compaq 3.31 families. DR-DOS 6/7
were never wired up because the VHD path uses
`LegacyDosQemuInstaller` directly (orthogonal to the asset
resolver), so nothing tripped over the gap until somebody asked
for a DR-DOS floppy IMG.

## Fix — verbatim Disk 1 copy

Both DR-DOS archives ship bootable Disk 1 images that are
byte-for-byte authentic install media:

- **DR-DOS 6.0** (5.25" 6-disk archive) — `Disk01.img` is a
  360 KiB DSDD floppy containing IBMBIO.COM + IBMDOS.COM +
  COMMAND.COM + drivers.
- **DR-DOS 7.03** (Caldera distribution) — `Installation &
  Utilities 1.img` is a 1.44 MiB floppy containing the same
  three system files plus the SETUP installer.

The cleanest fix is the same pattern that COMPAQ2, COMPAQ3 and
PCDOS3 already use: **verbatim copy** of Disk 1 to the output
floppy. This preserves DR-DOS's native boot sector + IBMBIO
layout without dosforge having to ship a DR-DOS-specific FAT12
boot loader template or guess at IBMBIO load offsets.

### Backend (`src/dosforge/disk.py`)

- **`verbatim_floppy_modes` table** extended with:
  ```
  BootMode.DRDOS6: ("Digital Research DR DOS 6.0 (drdos6)", FloppyType.F360K),
  BootMode.DRDOS7: ("Caldera DR-DOS 7.03 (drdos7)",      FloppyType.F1440K),
  ```
  Same code path that already handles COMPAQ2/COMPAQ3/PCDOS3 —
  no new helpers added. `_LegacyDosInstallDescriptor`s for
  DRDOS6/DRDOS7 were already in place from v0.9.10's VHD work;
  the verbatim branch reuses `extract_legacy_dos_install_archive`
  + `shutil.copyfile` to emit the floppy.

### Smoke matrix (`scripts/build-smoke-matrix.py`)

- **DRDOS6 + DRDOS7 removed from `_IMG_UNSUPPORTED_MODES`** —
  the dict now only lists modes that genuinely can't produce a
  static-bootable IMG (MSDOS6, MSDOS71, PCDOS, PCDOS2000,
  PCDOS3, COMPAQ3, FOURDOS).
- **`_DEFAULT_FLOPPY[BootMode.DRDOS6] = F360K`** — the 5.25"
  6-disk WinWorldPC archive only ships 360 KiB floppies, so
  the Tier-1 representative floppy for DR-DOS 6 is now 360k.
  DR-DOS 7 continues to use the default 1440k (matches its
  1.44 MiB Disk 1).

## How to verify

```bash
# Build the two new cases
sudo -v && scripts/build-smoke-matrix.py --filter '^img-drdos'

# Expected:
#   [1/2] img-drdos6-na-360k-sysfmt-minimal-nopayload   ✅ PASS
#   [2/2] img-drdos7-na-1440k-sysfmt-minimal-nopayload  ✅ PASS

# Confirm the produced floppies contain authentic DR-DOS system files
mdir -i .../img-drdos6-na-360k-sysfmt-minimal-nopayload.img ::
mdir -i .../img-drdos7-na-1440k-sysfmt-minimal-nopayload.img ::
# Both should list IBMBIO.COM, IBMDOS.COM, COMMAND.COM with
# the original 1992/1999 timestamps.

# Boot in 86Box with a Pentium-class profile, A: drive:
#   - DR-DOS 6 floppy should reach Caldera DR-DOS 6.0 A:\> banner
#   - DR-DOS 7 floppy should reach DR-DOS 7.03 A:\> banner
```
