# dosforge v0.9.44 — IBM 8088 boot mode: real per-DOS asset folders + form reorder

Patch release on top of v0.9.43.

## What was wrong

1. Picking *Boot OS = IBM PC 8088/V20* in the Windows GUI
   pre-populated the *Boot assets directory* field with
   `ibm8088`, but there is no `dosassets/ibm8088/` folder. The
   real per-DOS-version assets live in `dosassets/msdos33/`
   (for DOS 3.3) and `dosassets/msdos5/` (for DOS 5.0).
2. The *Boot assets directory* field sat above *IBM DOS
   version*, so it stayed wrong after the user picked the DOS
   version below it.

## What changed

* `formlogic.default_boot_assets_for` now takes the IBM DOS
  version and maps IBM 8088 mode to the **real** asset folder:

  | IBM DOS version | Pre-populated path |
  | --- | --- |
  | DOS 3.3 (default) | `msdos33` |
  | DOS 5.0           | `msdos5`  |

* `coerce_on_boot_change` now passes `ibm_dos_version` through,
  so picking the boot mode populates the right default.
* `coerce_on_ibm_version_change` now re-snaps the assets
  directory when the user flips DOS 3.3 ↔ DOS 5.0, **unless**
  they have already customized the field to a non-default value
  (`""`, `"msdos33"`, `"msdos5"`, or the legacy `"ibm8088"` are
  treated as defaults and get re-snapped; anything else is left
  alone).
* Windows GUI *Boot* card reordered so *Boot assets directory*
  is now the **last** field, below *IBM DOS version*. The user
  now picks the OS and DOS version first, and only then sees
  the pre-populated assets path -- no more stale `ibm8088`
  default surviving in the UI.

Linux TUI inherits the formlogic fix automatically (same
`default_boot_assets_for` + coercer logic). The TUI's field
order is unchanged.

## Tests

* `tests/test_formlogic.py::test_default_boot_assets_for_each_mode[BootMode.IBM8088]`
  updated to expect `"msdos33"` instead of `"ibm8088"`.
* All 57 formlogic tests green.
* Additional ad-hoc behavior check covers:
  * IBM8088 + DOS33 → `msdos33`
  * IBM8088 + DOS50 → `msdos5`
  * Flipping the DOS version re-snaps the path.
  * Custom paths (`/my/custom/path`) are preserved.
  * Stale `ibm8088` defaults from earlier builds get upgraded
    automatically.

## Install

### Linux

```bash
curl -L -o /tmp/dosforge.tar.gz \
  https://github.com/flynnsbit/dosforge/releases/download/v0.9.44/dosforge-0.9.44-linux.tar.gz
tar -xzf /tmp/dosforge.tar.gz -C /tmp
cd /tmp/dosforge-0.9.44 && sudo ./install.sh
```

### Windows

Download `dosforge-0.9.44-windows-x64.zip` or
`dosforge-0.9.44-cli-windows-x64.zip`, extract, run
`dosforge.exe`.
