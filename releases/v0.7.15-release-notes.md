# dosforge v0.7.15

Two small TUI fixes.

## 1. `...` browse buttons now flush against the input field

In v0.7.14 we removed the 1-cell empty gap to the right of the
button by zeroing `margin-right`, but left a 1-cell gap on the
*left* (between the Input and the Button). The user reported that
the button should be glued directly to the right side of the input
with no gap.

Set `margin-left: 0` on `.path-row Button` so the layout is now:

```
[Input.....................................][...]
                                        flush ↑
```

instead of:

```
[Input.....................................] [...]
                                          gap ↑
```

Affects every path row in the TUI: Output path, Boot assets
directory, Custom payload directory, file-tools Open / Extract.

## 2. Force `textual-dark` theme on TUI launch

Set `self.theme = "textual-dark"` in `DosForgeApp.on_mount()` so the
TUI always launches with the dark theme regardless of:

- the user's terminal color palette (light / dark);
- environment variables that some Textual versions consult to
  auto-detect light vs dark mode;
- system-level "appearance" preferences propagated through
  TERM_PROGRAM_COLORS or COLORFGBG.

The dosforge CSS palette (`$primary`, `$accent`, `$boost`, `$text`,
`$surface`) was tuned against the dark theme — forcing it
guarantees the rendered colors match what we styled against on
both Linux and Windows. Wrapped in a defensive try/except for
Textual versions older than 0.86 that didn't expose
`App.theme` as a writable reactive.

## What didn't change

- GUI (`dosforge gui`) — Tkinter `sv_ttk` theme is already
  initialized to dark and doesn't have a path-row gap issue.
- All other Button styles, path-row geometry, Input width
  (`width: 1fr`) — unchanged.
