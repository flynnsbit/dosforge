# dosforge v0.9.46 release notes

## Summary

Follow-up to v0.9.45: defaulting *Boot=IBM PC 8088/V20* in the form
landed you at *Size=32M* + *Controller=MFM*, but DOS 3.3 caps FAT16
at exactly 32 MiB and MFM auto-derive (v0.9.45) rounds 32M up to
the next cylinder boundary = 32.008 MiB, which then fails:

    "MS-DOS 3.3 IBM 8088/V20 profile images must not exceed 32 MiB."

The error told users to "type 31M" — but the default was 32M out
of the box, so the form was broken on first use.

## What changed

**`src/dosforge/formlogic.py` `apply_ibm_default_size`**

The default size is now context-aware:

| Controller | DOS version | Default size |
|-----------|-------------|--------------|
| MFM (auto-derive: no BIOS preset, no custom CHS) | DOS 3.3 | **31M** |
| MFM (auto-derive) | DOS 5.0 | 32M |
| IDE / explicit BIOS preset / custom CHS | any | 32M |

31M rounds to 31.011 MiB on MFM cylinder boundaries — safely
under DOS 3.3's 32 MiB cap.

Flipping the *IBM DOS Version* dropdown between 3.3 ↔ 5.0 now
re-snaps the default appropriately (31M for DOS33+MFM, 32M for
DOS50).

Users can still type any size manually within the relevant caps:

- DOS 3.3 + MFM: up to ~31.97 MiB (under 32 MiB cap)
- DOS 5.0 + MFM: up to ~127 MiB (MFM ceiling)
- DOS 3.3/5.0 + IDE: full DOS-version cap (32 MiB / 504 MiB)
