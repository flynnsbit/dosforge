# dosforge v0.9.43 — Image Tools extract accepts DOS drive-letter paths

Patch release on top of v0.9.42.

## What was wrong

Typing a natural DOS path like `C:\CONFIG.SYS` into the Image
Tools → *Extract* box (Windows GUI or Linux TUI) produced:

```
mcopy: File "::/C:/CONFIG.SYS" not found
```

`mcopy -i <image>` already binds the image as the only drive,
so an extra `C:\` prefix is meaningless. The path normalizer
wasn't stripping it, so mtools tried to look up a literal
`/C:/CONFIG.SYS` and failed.

## Fix

`_normalize_dos_path` in `src/dosforge/image_ops.py` now strips
a leading DOS drive letter (`C:`, `c:`, `D:`, …) before
prepending the `::` mtools sentinel. Both `C:\CONFIG.SYS` and
`/CONFIG.SYS` now resolve to `::/CONFIG.SYS`.

Examples that now work:
* `C:\CONFIG.SYS` → `::/CONFIG.SYS`
* `c:CONFIG.SYS` → `::/CONFIG.SYS`
* `C:\DOS\HIMEM.SYS` → `::/DOS/HIMEM.SYS`
* `D:\GAMES\DOOM\DOOM.EXE` → `::/GAMES/DOOM/DOOM.EXE`
* `C:` / `C:\` → `::/` (root listing)

The pre-existing styles (`/CONFIG.SYS`, `CONFIG.SYS`,
`\CONFIG.SYS`, empty/`/`) keep working unchanged.

Hint text on both UIs updated to advertise both forms:
*"Enter a DOS path to extract, e.g. /CONFIG.SYS or
C:\\CONFIG.SYS"*.

## Tests

* `tests/test_image_ops_path.py` (new): 12 parametrized cases
  covering drive-letter prefixes, plain DOS paths, root, and
  empty input. All green.
* `tests/test_inspect.py`, `tests/test_core_modules.py` — 30/30
  unchanged.

## Install

### Linux

```bash
curl -L -o /tmp/dosforge.tar.gz \
  https://github.com/flynnsbit/dosforge/releases/download/v0.9.43/dosforge-0.9.43-linux.tar.gz
tar -xzf /tmp/dosforge.tar.gz -C /tmp
cd /tmp/dosforge-0.9.43 && sudo ./install.sh
```

### Windows

Download `dosforge-0.9.43-windows-x64.zip` or
`dosforge-0.9.43-cli-windows-x64.zip`, extract, run
`dosforge.exe`.
