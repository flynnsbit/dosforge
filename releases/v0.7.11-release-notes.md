# dosforge v0.7.11

Adds 4 new bootable DOS variants in one drop, all using the
controller-first VHD model shipped in v0.7.0 and the auto-extract
`.7z` install pipeline added in v0.6.17.

## New boot modes

| Mode | Release | Media | OEM stamp | Format | Cap |
|---|---|---|---|---|---|
| `msdos6` | MS-DOS 6.0 (Mar 1993) | 3× 1.44 MB | `MSDOS5.0` (6.0 didn't bump the OEM string until 6.22) | FAT16 | standard |
| `compaq3` | MS-DOS 3.00 Compaq OEM (Apr 1985) | 2× 360 KB DSDD | `IBM  3.3` | FAT12 | 16 MiB |
| `drdos6` | Digital Research DR DOS 6.0 (Oct 1991) | 4× 720 KB DSDD | `IBM  3.3` | FAT12 / FAT16 | 32 MiB |
| `drdos7` | Caldera DR-DOS 7.03 (Jan 1999) | 5× 1.44 MB | `DRDOS  7` | FAT12 / FAT16 (BIGDOS) | 2 GiB |

### `msdos6` — MS-DOS 6.0
Sibling of `msdos5` / `msdos622`. First DoubleSpace release; predates
the Stac lawsuit. Same `FORMAT C: /S` install pipeline inside QEMU
from `Disk1.img`. Sources from the WinWorldPC `Microsoft MS-DOS 6.0
Plus Enhanced Tools (3.5).7z` archive (auto-extracted via py7zr).

### `compaq3` — Microsoft MS-DOS 3.00 [Compaq OEM]
Compaq-branded sibling of `pcdos3`. DOS 3.0 BPB (with
hidden_sectors), so boots on any standard MFM/IDE BIOS. Uses
IBMBIO.COM / IBMDOS.COM naming (Compaq adopted IBM's system-file
names for 3.0). Defaults to MFM controller for 1985-authentic
Compaq DeskPro / Portable Plus hardware (override with
`--disk-controller ide`). Sources from
`Microsoft MS-DOS 3.00 [Compaq OEM] (5.25-360k).7z`.

### `drdos6` — Digital Research DR DOS 6.0
DR-DOS competitor to MS-DOS 5.0 with full EMM386 + DPMI + SuperStor
compression (SSTORDRV.SYS). BPB OEM stamp `IBM  3.3` so DR-DOS 6
boots on any standard BIOS. Disk1 ships the full DR-DOS toolchain
(COMMAND, SYS, FORMAT, FDISK) + the interactive INSTALL wizard;
dosforge bypasses the wizard via `FORMAT C: /S` in QEMU. Sources
from `Digital Research DR DOS 6.0 (10-16-1991) (3.5-720k) (alt).7z`.

### `drdos7` — Caldera DR-DOS 7.03
Final retail DR-DOS release. Includes FAT16B / BIGDOS (>32 MiB FAT16
partitions up to 2 GiB) and the DR-DOS multitasker (TASKMGR). BPB
OEM `DRDOS  7`. Disk1 ships the full DR-DOS 7 toolchain + INSTALL
+ SETUP2 wizard (bypassed via scripted AUTOEXEC.BAT). FAT16 only at
this initial wiring (2 GiB cap) — FAT32 LBA can land as a follow-up
via `drdos7_fat32_profile` mirroring `pcdos71_profile`. Sources
from `Caldera DR-DOS 7.03 (01-07-1999) (3.5-1.44mb).7z`.

## Setup

For each mode, drop the WinWorldPC `.7z` archive into the matching
asset directory:

```bash
~/.local/share/dosforge/dosassets/msdos6/Microsoft MS-DOS 6.0 Plus Enhanced Tools (3.5).7z
~/.local/share/dosforge/dosassets/compaq3/Microsoft MS-DOS 3.00 [Compaq OEM] (5.25-360k).7z
~/.local/share/dosforge/dosassets/drdos6/Digital Research DR DOS 6.0 (10-16-1991) (3.5-720k) (alt).7z
~/.local/share/dosforge/dosassets/drdos7/Caldera DR-DOS 7.03 (01-07-1999) (3.5-1.44mb).7z
```

Then build:

```bash
dosforge create --media-type vhd --boot-mode msdos6  --format fat16 --size 128M --path msdos6.vhd
dosforge create --media-type vhd --boot-mode compaq3 --format fat12 --size 10M  --path compaq3.vhd
dosforge create --media-type vhd --boot-mode drdos6  --format fat16 --size 32M  --path drdos6.vhd
dosforge create --media-type vhd --boot-mode drdos7  --format fat16 --size 128M --path drdos7.vhd
```

Each per-mode `dosassets/<mode>/readme.txt` (sync'd into the wheel
skeleton) carries the full provenance + expected layout.

## TUI / GUI surfaces

The 4 new modes show up in:
- TUI Create wizard `boot-mode` dropdown
- GUI `boot-mode` combobox
- `dosforge create --help` boot-mode list

Compatible format choices auto-snap when the user picks one of the
new modes (FAT12 + 16 MiB for compaq3; FAT16 + 32 MiB for drdos6;
FAT16 + 2 GiB for drdos7; FAT16 default for msdos6).

## Notes

- The DR-DOS modes intentionally bypass `INSTALL.EXE` / `SETUP2`
  because driving those interactive wizards from QEMU input
  injection is brittle. The system files DR-DOS lays down via
  `FORMAT C: /S` (IBMBIO.COM, IBMDOS.COM, COMMAND.COM) are
  identical to what the wizard would write.
- All 4 modes are validated through dosforge's per-mode form-snap
  rules in `formlogic.py` and the boot-mode × controller validation
  matrix in `disk.py` — invalid combinations (e.g. drdos7 + FAT12
  on a 1 GiB VHD) raise actionable errors before any disk writes
  start.
- No `dosforge` schema changes. CLI flags, TUI / GUI state-machine,
  Linux / Windows install scripts, and CI release workflows are
  unchanged from v0.7.10.
