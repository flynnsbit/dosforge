# dosforge v0.9.21

## Fix: FULL install profile now works for 6 legacy DOS boot modes

`BootAssetResolver.resolve()` was missing dispatch for six boot modes
that ship via the QEMU FORMAT C: install path:

- `BootMode.DRDOS6` (Digital Research DR DOS 6.0)
- `BootMode.DRDOS7` (Caldera DR-DOS 7.03)
- `BootMode.PCDOS2000` (IBM PC-DOS 2000)
- `BootMode.COMPAQ2` (Compaq DOS 2.11)
- `BootMode.COMPAQ3` (Microsoft MS-DOS 3.00, Compaq OEM)
- `BootMode.PCDOS3` (IBM PC-DOS 3.00)

`MINIMAL` profile builds worked (the resolver isn't called when the
QEMU FORMAT C: /S step covers the entire install), but `FULL` profile
hit `_stage_legacy_dos_full_profile` which always invokes
`boot_resolver.resolve(request)` to discover the DOS-tools payload to
stage under `C:\DOS\`. The unhandled boot modes fell through to the
fallthrough `raise ValidationError(f"Unsupported boot mode: ...")` and
the GUI/CLI surfaced *"Unsupported boot mode: drdos6"* after the
otherwise-successful QEMU install.

### Changes

- **Six new resolver methods** in `BootAssetResolver` (`_resolve_drdos6`,
  `_resolve_drdos7`, `_resolve_pcdos2000`, `_resolve_compaq2`,
  `_resolve_compaq3`, `_resolve_pcdos3`), each delegating to the
  existing `_resolve_legacy_dos` factory with
  `boot_template_required=False`.
- **New `boot_template_required` parameter** on `_resolve_legacy_dos`
  and `_try_resolve_legacy_dos_from_install_images` (default `True`,
  preserves existing behavior).  When `False`, missing FAT16 boot
  templates are filled with a 512-byte zero placeholder instead of
  raising — these boot modes write their authentic boot sector via
  the QEMU `FORMAT C:` step, so the asset-resolver template is never
  consumed for them.
- **Six new dispatch arms** in `BootAssetResolver.resolve()`.

### User-facing effect

Dropping a WinWorldPC `.7z` archive (or pre-extracted `.img`, or a
directory tree) into `dosassets/drdos6/`, `dosassets/drdos7/`,
`dosassets/pcdos2000/`, `dosassets/compaq2/`, `dosassets/compaq3/`,
or `dosassets/pcdos3/` and choosing **FULL** install profile now
produces a VHD with:

- `C:\IBMBIO.COM` / `C:\IBMDOS.COM` (or `IO.SYS` / `MSDOS.SYS`)
- `C:\COMMAND.COM`
- `C:\CONFIG.SYS` + `C:\AUTOEXEC.BAT`
- `C:\DOS\` populated with the install media's full tool set
  (FDISK, FORMAT, ATTRIB, CHKDSK, KEYB, MEM, MODE, SYS, XCOPY,
  etc. — DR-DOS 6 0.9.21 sample run staged 20 tools, ~316 KB)

Verified end-to-end on Windows with DR-DOS 6 32 MiB FAT16 VHD using
the `Digital Research DR DOS 6.0 (10-16-1991) (3.5-720k) (alt)` 7z.
