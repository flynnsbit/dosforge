# dosforge v0.9.34

## Grow VHD: per-step progress + honest time estimate

Previously the Grow Disk tab showed a generic spinner with the
misleading caption "(this may take 10-30 s)..." for the entire
operation.  In reality a grow that uses the default headless boot
probe burns 60-120s easily (qemu-nbd attach + fresh FreeDOS create
+ 90s QEMU boot timeout), and the user had no visibility into which
step was actually consuming wall-clock when something stalled.

### What's new

- **`grow_vhd` / `perform_grow` accept a `progress_callback`** parameter
  that's invoked with short stage labels at the start of every one
  of the 8 grow steps (snapshot, validate, extract, build, inject,
  stage, probe, swap).  Backward-compatible default of `None` keeps
  the CLI silent path unchanged.
- **The TUI spinner narrates each step in-place** while it runs:
  > Step 4/8: Building fresh freedos VHD at 134,217,728 bytes (may need sudo for qemu-nbd)...
  > Step 7/8: Headless boot probe -- booting grown VHD in QEMU (up to 90s; uncheck 'Headless boot probe' to skip)...
- Every stage transition is also appended to the persistent status
  log (`[..] Step N/8: ...`) so the user can scroll back via
  `Ctrl+Y` "Copy log" to share a full trace if anything fails.
- **Initial spinner caption is now honest** about timing, e.g.:
  > Grow freedos-32M-FAT16.VHD -> 134,217,728 bytes (extract + rebuild + reinject + ~60-90s headless boot probe)...
  When the boot-probe checkbox is unchecked, the caption ends with
  `(boot probe disabled)` instead.
- **Boot-probe checkbox label updated** to call out the cost:
  > Headless boot probe (adds ~60-90s; verifies new VHD boots before swap)
  so users know they can uncheck it for quick iteration on already-trusted
  grows.

### Files touched

- `src/dosforge/grow.py` -- add `progress_callback` kwarg to
  `grow_vhd`, forward to `perform_grow`.
- `src/dosforge/_grow_impl.py` -- thread the callback through
  `perform_grow`'s 8 steps with descriptive stage labels.
- `src/dosforge/app.py` --
  * `_grow_worker` now passes a `call_from_thread`-bridged callback.
  * New `_set_spinner_message()` updates the live spinner caption
    and appends each transition to the log.
  * Initial spinner caption rewritten to mention the probe cost.
  * Boot-probe checkbox label gained "(adds ~60-90s; ...)" hint.

### Honesty note

The 10-30s estimate in earlier releases was wildly optimistic.  The
grow flow had not been exercised end-to-end during the v0.9.27 grow
v1 ship and the misleading spinner string slipped through.  This
release does not change any actual grow behaviour -- only how
honestly the UI reports what's happening.  A separate investigation
into the qemu-nbd / sudo hang reported in the field is still open.
