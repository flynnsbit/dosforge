# dosforge v0.7.13

UX cleanup — moved the **Boot assets directory** field from Step 3
into Step 1 (next to the Boot OS dropdown) and auto-populated it
based on the selected boot mode.

## Background

The previous wizard layout left the path that controlled *where
dosforge looks for an OS's install media* hidden away in Step 3.
This was especially confusing for the generic
`IBM PC-DOS (user-supplied install media)` option in v0.7.12 — users
saw the "user-supplied" label but no obvious supply field anywhere
on the Boot OS screen.

## Change

**TUI (`dosforge tui` / `dosforge`):**
- Step 1 — Boot OS now shows:
  - Boot OS [dropdown]
  - **Boot assets directory or install image** [path input + browse] ← **MOVED HERE**
  - FreeDOS source (when applicable)
  - DOS install profile (when applicable)
  - IBM DOS version (when applicable)
- Step 3 renamed: "Boot assets and payload" → **"Payload and extras"**
- Step 3 now holds just: Custom payload directory, FreeDOS download
  URL, Fetch FreeDOS / Fetch PC-DOS 7.1 buttons.

**GUI (`dosforge gui`):**
- The "Boot" card now shows the Boot assets directory field right
  below Boot OS (rows 0 → 1).
- The former "Assets & payload" card is renamed to **"Payload and
  extras"** and now contains only custom-payload + FreeDOS URL.

## Auto-populate behavior

When you pick a boot mode, the Boot assets Input is pre-populated
with the bare subdir name dosforge expects in `dosassets/<mode>/`:

| Boot OS | Pre-filled Boot assets value |
|---|---|
| None (data disk only) | _(empty — field hidden)_ |
| FreeDOS | `freedos` |
| MS-DOS 6.22 | `msdos622` |
| MS-DOS 7.10 / Win95 OSR2 | `msdos71` |
| IBM PC-DOS (other version) | `pcdos` |
| IBM PC-DOS 3.00 | `pcdos3` |
| Caldera DR-DOS 7.03 | `drdos7` |
| _…etc, one per boot mode_ | matches `dosassets/<mode>/` name |

You can still **edit the field after picking** — type a full path to
a custom directory, or browse with the `…` button. The auto-fill is
treated like every other auto-snap (disk format, controller, size):
it overwrites on each mode change so the default is predictable.

This makes the previously-confusing "IBM PC-DOS (user-supplied
install media)" entry self-explanatory: when you pick it, the field
right below shows `pcdos`, telling you exactly which `dosassets/`
subdir dosforge expects (or where to point the browse button if you
keep your install media elsewhere).

## New `formlogic.default_boot_assets_for()` helper

Public API addition for any future UI surfaces or scripts that need
the canonical asset-dir name for a given `BootMode`:

```python
from dosforge import formlogic as fl
from dosforge.models import BootMode

fl.default_boot_assets_for(BootMode.PCDOS)    # 'pcdos'
fl.default_boot_assets_for(BootMode.MSDOS622) # 'msdos622'
fl.default_boot_assets_for(BootMode.NONE)     # ''
```

`coerce_on_boot_change()` now calls this helper as its first step
so every boot-mode branch (including the COMPAQ2 / PCDOS3 / COMPAQ3
early-return branches) snaps `boot_assets` consistently.

## What didn't change

- `BootMode` enum and CLI `--boot-mode` flag — no backend changes.
- Per-mode validation (FAT12-only caps, controller defaults,
  Windows-supported gate, etc.) — same as v0.7.12.
- `--boot-assets-path` CLI flag — same as v0.7.12.
- The 4 version-specific PC-DOS modes (`pcdos3`, `pcdos7`,
  `pcdos2000`, `pcdos71`) — unchanged.
- All 19 dropdown labels (set in v0.7.12) — unchanged.
