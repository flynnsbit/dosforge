# dosforge v0.7.9 — installer "stale dosforge on PATH" detection

Hot-fix for `scripts/install.sh` after a user reported that
`dosforge --version` still didn't work after upgrading to v0.7.8 —
turned out to be a pre-existing `dosforge` somewhere else on `PATH`
taking priority over the installer's symlink.

## Bug

The v0.7.8 wheel contains the `--version` flag correctly (verified
by extracting the published asset).  But if the user has another
`dosforge` from an earlier `pipx install dosforge`, a global
`pip install --user dosforge`, or a mise/asdf-managed Python shim
that comes earlier on `PATH`, then `dosforge --version` runs that
stale binary and fails with `unrecognized arguments: --version`.

No way to tell from the install output that anything was wrong —
everything looked successful.

## Fix

After symlinking `~/.local/bin/dosforge`, the installer now uses
`command -v dosforge` + `readlink -f` to verify that the resolved
binary matches the just-installed venv binary.  If not, it prints
a clear warning with the most common culprits and one-line fixes:

```
WARN: Another 'dosforge' is taking priority on your PATH:
WARN:     /home/shawn/.local/share/mise/shims/dosforge -> /home/shawn/.local/share/mise/installs/python/3.14.0/bin/dosforge
WARN:     (this install: /home/shawn/.local/share/dosforge/venv/bin/dosforge)
WARN:
WARN: Common culprits:
WARN:   - pipx install dosforge from before this installer existed
WARN:     -> fix:  pipx uninstall dosforge
WARN:   - global 'pip install --user dosforge' on a different Python
WARN:     -> fix:  pip uninstall dosforge  (run with the offending Python)
WARN:   - mise/asdf-managed shim ahead of ~/.local/bin on PATH
WARN:     -> fix:  move 'export PATH="$HOME/.local/bin:$PATH"' AFTER
WARN:              the mise/asdf shim line in your shell rc
WARN:
WARN: Until that's fixed, run the installed version directly:
WARN:     /home/shawn/.local/share/dosforge/venv/bin/dosforge --version
```

This makes the failure mode immediately obvious instead of silent.

## Files changed

- `scripts/install.sh`: added the post-symlink PATH-priority check
- `pyproject.toml` + `src/dosforge/__init__.py`: 0.7.8 -> 0.7.9
- `releases/v0.7.9-release-notes.md`: this file

## Compatibility

100% behavior-compatible with v0.7.8.  Pure installer diagnostic
improvement.

## Re-running

```bash
curl -fsSL https://raw.githubusercontent.com/flynnsbit/dosforge/main/scripts/install.sh | bash
```

If you hit the "Another 'dosforge' is taking priority" warning,
apply the suggested fix and re-run.  Or just use the absolute path
shown to confirm the new install works:

```bash
~/.local/share/dosforge/venv/bin/dosforge --version
# dosforge 0.7.9
```
