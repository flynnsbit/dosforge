# dosforge v0.5.0-gui-pre1 — native Windows 11 GUI (preview 1)

This preview replaces the Windows Textual TUI experience with a proper
**native desktop GUI** built on stdlib **tkinter** themed by **Sun Valley
(`sv-ttk`)** — a clean Windows 11 / Fluent look with a blue accent and
light/dark support. **No purple.**

The GUI drives the existing, UI-agnostic backend (`DiskManager` +
`CreateRequest`) with **zero backend changes**, so disk/boot behavior is
identical to the CLI and TUI.

## What's new

- **Desktop GUI is the default on Windows.** Running `dosforge` (or the new
  windowed `dosforge-gui.exe`) opens the GUI. If the GUI can't start it falls
  back to the TUI automatically.
- **Fluent navigation rail** with five views matching the TUI feature set:
  - **New Disk** — grouped cards (Output / Media & geometry / Boot /
    Assets & payload) with dynamic show/hide driven by the shared
    `formlogic` rules, plus a live **Summary** card showing the effective
    request (including IBM8088 512M→32M, MartyPC fixed geometry, and
    BIOS-preset size locks).
  - **Browse** — lazy filesystem tree to pick an existing `.vhd/.img/.ima/.vfd`.
  - **Image Tools** — mtools `ls` / extract / open-in-file-manager (no admin).
  - **Mounts** — mount / unmount / list, with a Windows admin hint.
  - **Utilities** — privilege diagnostics + dependency preflight.
- **Light/dark toggle** with Win11 immersive dark title bar.
- **Per-monitor DPI awareness** for crisp text on HiDPI displays.

## How it's launched

- `dosforge` (no args): GUI on Windows, TUI on Linux/headless.
- `dosforge gui`: force the GUI (clear error if unavailable).
- `dosforge tui`: force the Textual TUI (still the default on Linux).
- All CLI subcommands (`create`, `check-deps`, `sudo-check`, …) unchanged.

## Architecture notes

- New pure module `dosforge.formlogic` mirrors the TUI's visibility +
  request-building rules and is covered by headless **golden tests**
  (`tests/test_formlogic.py`) so the GUI and TUI can't silently diverge.
- New `dosforge.capabilities` centralizes platform/backend gating shared by
  GUI and TUI.
- GUI package under `dosforge._gui/` (theme, widgets, worker, views).
- **Single serialized background worker** thread; all Tk updates marshaled to
  the main thread via `root.after`. No concurrent disk ops. No fake cancel —
  a persistent "Working…" status + busy bar instead. Closing the window
  during an operation prompts for confirmation.

## Packaging

- `windows/dosforge.spec` and `dosforge-lite.spec` now build a second
  **windowed** `dosforge-gui.exe` (`console=False`) alongside the console
  `dosforge.exe`, and bundle the `sv_ttk` Tcl theme assets via
  `collect_all`.

## Known limitations / follow-ups

- Extra mtools verbs the CLI exposes (`cat/get/put/rm/mkdir`) are out of
  scope for this preview (parity with the TUI only).
- GUI widget rendering is validated by a manual frozen smoke checklist; only
  the pure form logic is unit-tested (Tk needs a display).
