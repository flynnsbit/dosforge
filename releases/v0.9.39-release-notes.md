# dosforge v0.9.39

## Windows GUI: center the staging-DOS-path dialog over the app

User feedback after v0.9.38: *"when selecting the staging directory
the little popup box comes up in the top left corner and I almost
missed it, can it come up centered instead and look more like a
dialog box so the user doesn't miss that it still needs something?"*

### Root cause

`_add_staging` in `src/dosforge/_gui/grow_view.py` built the
"DOS destination path" prompt as a bare `tk.Toplevel(self)` with
no explicit `geometry(...)`. Tk gives un-positioned Toplevels the
window manager's default placement, which on Windows resolves to
the top-left corner of the screen — far away from the user's
attention focus on the DosForge main window — so the modal was
trivially missed even though `grab_set()` was blocking input on
the parent.

### Fix

`_add_staging` now:

* Wraps the body in a single padded `ttk.Frame(padding=18)` so
  the prompt no longer looks like a debug widget.
* Shows a bold header (*"Stage directory to DOS path"*), a wrapped
  "Host source:" block, and the entry's label as a normal
  paragraph instead of a single mashed multi-line label.
* Uses an `Accent.TButton` for **OK** and right-aligns the button
  row, matching the rest of the app's modal style.
* Calls `dialog.transient(self.winfo_toplevel())` (the top-level
  app, not the embedded Frame) so the WM treats it as a real
  child of the main window.
* Measures the parent app's `winfo_rootx/y/width/height` after
  `update_idletasks()`, then `dialog.geometry(...)` centers the
  modal horizontally and places it at 1/3 of the parent's height
  (so it sits visually centered without the OK button falling off
  the bottom of short screens).
* Forces `dialog.deiconify() + lift() + focus_force() + grab_set()`
  in that order so the modal is visible, on top, focused, and
  modal even if the user clicked back to the main window between
  the directory picker closing and the prompt opening.
* Hooks `WM_DELETE_WINDOW` so closing the modal via the OS title-bar
  X cancels cleanly (was a no-op before).

### Verification

* `python -c "import ast; ast.parse(open('src/dosforge/_gui/grow_view.py').read())"` — clean.
* Module imports cleanly: `from dosforge._gui import grow_view`.
* No behavior change outside the prompt — the existing
  `wait_window()` + `result["dest"]` machinery is unchanged.

### Install one-liners

**Linux:**

```bash
curl -fsSL https://github.com/flynnsbit/dosforge/releases/download/v0.9.39/dosforge-0.9.39-linux.tar.gz \
  | tar xz
./dosforge-0.9.39-linux/install.sh
```

**Windows (full GUI + CLI bundle):** download
`dosforge-0.9.39-windows-x64.zip` and extract; run `dosforge-gui.exe`.

**Windows (CLI only):** download
`dosforge-0.9.39-cli-windows-x64.zip` and extract; run `dosforge.exe --help`.
