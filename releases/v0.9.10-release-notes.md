# dosforge v0.9.10 — DR-DOS 6/7 install pipeline + multi-disk merge

Brings the DR-DOS family back into the smoke matrix. Previously
`vhd-drdos6-fat16` and `vhd-drdos7-fat16` were `SKIP`'d via
`_KNOWN_BROKEN` because the `FORMAT C: /S` step in the QEMU
install run completed but never laid down `IBMBIO.COM` /
`IBMDOS.COM` on C:.

Three things land together in this release:

1. **Two-step `FORMAT C:` + `SYS C:` install** for any profile
   that sets `use_sys_after_format=True`. DR-DOS's `FORMAT.COM /S`
   does not match MS-DOS/PC-DOS semantics under non-interactive
   stdin; running `SYS C:` as a separate explicit step is the
   DR-DOS-canonical way and is robust regardless of the BPB
   layout left behind by FORMAT.
2. **Supplementary-disk merge** for DOS install archives whose
   tools span multiple floppies. DR-DOS 6's WinWorldPC 5.25"
   6×360 KiB archive splits `IBMBIO`/`IBMDOS`/`COMMAND` (Disk01)
   from `FORMAT.COM`/`SYS.COM`/`FDISK.COM` (Disk06). The new
   merge step mcopies the per-profile required tools off
   sibling `DiskNN.img` images onto the boot floppy *before*
   the AUTOEXEC.BAT runs. Generalises to any future multi-disk
   DOS we want to pipeline.
3. **Diagnostic preservation on verify failure.** Previously
   only QEMU exit failures preserved the install floppy as
   `FAILED-QEMU-*.img`. Now post-QEMU verify failures (system
   files missing on C: despite `VHDMK.OK`) also preserve as
   `FAILED-VERIFY-*.img`, so the AUTOEXEC capture files
   (`STEP.TXT`, `FMT_OUT.TXT`, `SYS_OUT.TXT`, `CP_OUT.TXT`,
   `MBR_OUT.TXT`) survive for postmortem.

Tag: `v0.9.10` — Linux + Windows artifacts are built and uploaded
by CI in a single workflow run.

## Symptom (v0.9.9 and earlier)

`scripts/build-smoke-matrix.py` reported:

```
[24/42] vhd-drdos6-fat16-na-nosysfmt-minimal-nopayload
    ⏭️  SKIP  (DR-DOS 6.0 install pipeline known broken (FORMAT C: /S
       completes but system files don't transfer to C:\). Tracked
       as a v0.9.x follow-up.)
[25/42] vhd-drdos7-fat16-na-nosysfmt-minimal-nopayload
    ⏭️  SKIP  (DR-DOS 7.03 install pipeline known broken …)
```

End-to-end with the gate removed, post-install `mdir` of `C:\`
showed only `VHDMK.OK` and `COMMAND.COM`; `IBMBIO.COM` and
`IBMDOS.COM` were missing.

## Root cause

`legacy_dos_install._prepare_install_floppy()` emitted a
single-line install AUTOEXEC:

```
FORMAT C: /S < A:\YES.TXT > A:\FMT_OUT.TXT
```

DR-DOS's `FORMAT.COM` accepts `/S` but, when run from a
non-interactive stdin feed, silently no-ops the system-file
transfer step. The format itself completes, the partition is
written, but the IBMBIO/IBMDOS copy never runs.

Compounding this on DR-DOS 6: the 6-disk 5.25" archive that
WinWorldPC ships only has Disk01 (system files) auto-extracted
onto the boot floppy — `FORMAT.COM` and `SYS.COM` themselves
live on Disk06 and were never visible to the install run, so
even fixing the `/S` issue wouldn't have shipped a usable
formatter.

## What changed

### Backend (`src/dosforge/legacy_dos_install.py`)

- **New `LegacyDosInstallProfile` fields** — fully backward
  compatible defaults so every existing DOS profile is
  byte-identical to v0.9.9:
  - `use_sys_after_format: bool = False` — when True,
    `_prepare_install_floppy` emits `FORMAT C:` (no `/S`)
    followed by an explicit `SYS C:` step.
  - `sys_yes_input: bytes = b"Y\r\n"` — stdin for `SYS C:`.
  - `supplementary_disk_images: tuple[Path, ...] = ()` —
    sibling disk images to merge tools from.
  - `supplementary_disk_extract_globs: tuple[str, ...] = ()` —
    filename globs to mcopy off each supplementary disk
    (e.g. `("FORMAT.COM", "SYS.COM", "FDISK.COM")`).

- **`_merge_supplementary_disks()` helper** — for each
  supplementary disk image, mcopy any matching files onto the
  work floppy via mtools. Idempotent (skips files already
  present on the work floppy). Runs before AUTOEXEC injection.

- **`drdos6_profile()` auto-detection** — if the configured
  install image is named `Disk01.img` and `Disk02..Disk06.img`
  siblings exist (i.e. the 5.25" 6-disk archive), the profile
  now auto-populates `supplementary_disk_images` +
  `supplementary_disk_extract_globs=("FORMAT.COM", "SYS.COM",
  "FDISK.COM")`, plus a `pre_install_deletes` list that scrubs
  ~210 KiB of non-essential drivers (VIEWMAX, EMM386.SYS,
  HIDOS.SYS, ANSI.SYS, etc.) so the merged tools fit in the
  360 KiB floppy budget. Single-disk archives (e.g. the 3.5"
  4×720k variant referenced in the docstring) leave the
  supplementary fields empty.

- **`drdos7_profile()`** — sets `use_sys_after_format=True`.
  DR-DOS 7.03 ships everything (FORMAT, SYS, FDISK, INSTALL)
  on a single 1.44 MiB Disk 1, so no supplementary merge is
  needed.

- **Install orchestration in `install_system()`** —
  refactored into two nested `try` blocks so:
  - QEMU exit failures preserve as `FAILED-QEMU-<name>.img`
  - Verify failures preserve as `FAILED-VERIFY-<name>.img`

  Both use `Path.replace()` so each failure path leaves
  exactly one postmortem artifact (no duplicate copies).

### Smoke matrix (`scripts/build-smoke-matrix.py`)

- **Removed DR-DOS 6/7 from `_KNOWN_BROKEN`** — the dict is
  now empty (kept for future use). `vhd-drdos6-fat16` and
  `vhd-drdos7-fat16` now exercise the new pipeline.

### Tests (`tests/test_legacy_dos_install.py` — new)

- 9 new unit tests covering:
  - Two-step `FORMAT C:` + `SYS C:` AUTOEXEC generation.
  - One-step AUTOEXEC stays byte-identical when
    `use_sys_after_format=False` (regression guard for every
    pre-existing DOS profile).
  - Supplementary-disk merge mcopies the right files.
  - Merge skips files already present on the work floppy
    (no-op when supplementary disks are unused).
  - `drdos6_profile` 5.25" archive auto-detection populates
    the supplementary fields + scrub list.
  - `drdos6_profile` single-disk archive leaves supplementary
    fields empty.
  - `drdos7_profile` always sets `use_sys_after_format=True`.
  - QEMU-failure path preserves as `FAILED-QEMU-*.img`.
  - Verify-failure path preserves as `FAILED-VERIFY-*.img`.

## How to verify

```bash
# Rebuild the previously-skipped DR-DOS cases
sudo -v && scripts/build-smoke-matrix.py --filter drdos

# Confirm system files landed on C:
qemu-nbd --connect=/dev/nbd0 vhd/vhd-drdos6-fat16-na-nosysfmt-minimal-nopayload.vhd
mdir -i /dev/nbd0p1 :: | grep -iE 'IBMBIO|IBMDOS|COMMAND'
sudo qemu-nbd --disconnect /dev/nbd0

# Boot in 86Box with the per-mode profile from MANIFEST.md
```

If the install fails for any reason, the postmortem floppy is at
`~/.local/state/dosforge/cache/legacydos/FAILED-VERIFY-legacydos-sys-*.img`
with the `A:\STEP.TXT`, `A:\FMT_OUT.TXT`, `A:\SYS_OUT.TXT`,
`A:\CP_OUT.TXT`, `A:\MBR_OUT.TXT` capture files for inspection.

## Risks / known unknowns

- The two-step `FORMAT` + `SYS` approach is the documented
  DR-DOS-canonical install pattern but is shipped here without
  a Linux-host live run in CI (sudo gates QEMU/nbd in test
  environments). Bake-in by user smoke run is the actual
  validation step. If verify fails, the new
  `FAILED-VERIFY-*.img` artifacts are diagnostic gold for a
  v0.9.11 follow-up.
- DR-DOS 6 multi-disk merge currently targets the 5.25"
  6×360 KiB layout only. The 3.5" 4×720 KiB archive referenced
  in the `drdos6_profile` docstring should already work without
  the merge step (Disk 1 has everything), but it isn't shipped
  on this dev box and isn't currently in the test matrix.
