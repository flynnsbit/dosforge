# DOSForge v0.4.0 — TUI Redesign Preview 4

Fourth pre-release of the wizard-style TUI. Focus: kill the visual
artifacts (hash/stripe patterns, missing glyphs, flashing picker)
reported on pre3.

## What changed since pre3

### 1. No more hash/stripe pattern on inputs and buttons

Windows `conhost` (the legacy Console Host that hosts CMD and many
script-launched terminals) **cannot do true alpha-blending**. CSS
colors like `$primary 20%` were being approximated as a stipple /
checker pattern of `$primary` cells over the background — visually
reading as "hash marks" or "stripes" covering focused inputs and
hovered buttons.

Every alpha-percentage color on backgrounds and borders has been
replaced with a solid palette color (`$primary`, `$accent`, `$boost`,
`$surface`, `$panel`, `$warning`, `$error`). The focused input now
gets a solid 2-cell accent border; hovered buttons get a solid
darker shade. No more stipple.

### 2. ASCII-only wizard progress markers

The progress indicator changed from `●○✓` (BMP but not guaranteed in
Consolas / Lucida Console) to `[>] [ ] [x]`. Back/Next arrows changed
from `← →` to `< >` for the same reason.

Guarantees no missing-glyph boxes regardless of the user's terminal
font. Earlier reports of "boxes in the progress indicator" stemmed
from the supplementary characters not having a glyph in the user's
font.

### 3. Native file picker actually works in bundled .exe

The `...` browse buttons launch a native Win32 file/folder picker via
`tkinter.filedialog`. PyInstaller's `excludes=['tkinter', ...]` was
preventing `tkinter` from being bundled, so the import failed silently
in the .exe and the fallback "flash" UX ran instead.

Fixes:
- Removed `tkinter` from `excludes` in `dosforge.spec` and
  `dosforge-lite.spec`.
- Added `tkinter`, `tkinter.filedialog`, `tkinter.ttk` as explicit
  hidden imports so PyInstaller's static analysis can't drop them.
- Bundle grows ~5–7 MB to include the Tcl/Tk runtime, but the picker
  actually works now.

### 4. Better picker fallback UX

When the native picker is unavailable (rare edge case), the wizard
now **stays put** instead of flash-switching tabs. Shows a Textual
toast notification + status hint inviting the user to use the Browse
tab manually. No more disorienting tab flips.

## Carry-over from pre1–pre3

- 4-step wizard (Media → Boot → Payload → Confirm) with `[>] [ ] [x]`
  progress, scroll-area for step content, pinned Back/Next nav at the
  bottom (no more nav buttons getting pushed off-screen)
- 5 tabs: New Disk, Browse, Mounts, Connections, Settings
- Live summary panel beside the wizard
- Quick Create button — bypasses the wizard once required fields are set
- Ctrl+1..5 keybinds for tab switching
- Console auto-maximizes on Windows at launch
- All 43 widget IDs preserved (no regression for users with muscle
  memory or external tooling)

## Download

The three artifacts attached to this release:

- `dosforge-0.4.0-tui-redesign-pre4-windows-x64.zip` — full bundle
  (~135 MB) — TUI + CLI + DOS install assets + DOSBox-X
- `dosforge-0.4.0-tui-redesign-pre4-lite-windows-x64.zip` — lite
  bundle (~50 MB) — TUI + CLI + readmes only (bring your own DOS
  install media)
- `dosforge-0.4.0-tui-redesign-pre4-cli-windows-x64.zip` — CLI-only
  bundle (~40 MB) — no TUI

Unzip, run `dosforge.exe`. The TUI launches by default; `dosforge --help`
for CLI commands.

## Known limitations

- Lots of vertical dead space below step-3 content. Acceptable for a
  wizard layout but may shrink in a future pre-release if requested.
- The CLI-only bundle (`-cli-`) does not include `tkinter` (no GUI
  needed), so it has no native picker UI — but it also has no TUI
  buttons that would trigger one.
