# dosforge v0.5.0-gui-pre8 — drop lite bundle, restore TUI in full

The lite Windows bundle is gone. The release now publishes just two
zips:

- **Full** (`dosforge-<ver>-windows-x64.zip`): ships everything —
  console launcher (`dosforge.exe`) with full TUI / GUI / CLI access
  via subcommands, plus the windowed `dosforge-gui.exe`.
- **CLI-only** (`dosforge-<ver>-cli-windows-x64.zip`): a slim
  `dosforge.exe` with no TUI / GUI imports for users who only need
  the command-line verbs.

## What's new

- New `dosforge.cli.full_console_main()` entry point — same `tui` /
  `gui` / `create` / ... subcommand set as the pip-installed
  `dosforge` script. Run with no arguments to see the help with
  examples; run `dosforge tui` to launch the Textual TUI; run
  `dosforge gui` (or double-click `dosforge-gui.exe`) for the GUI.
- `windows/dosforge_entry.py` now dispatches to `full_console_main`
  when `textual` is importable (full bundle) and to `cli_only_main`
  when it isn't (CLI-only bundle). No per-bundle entry script.
- `windows/dosforge.spec` re-collects the textual / rich / pygments /
  markdown_it / psutil TUI stack and drops them from `excludes`.
- `windows/dosforge-lite.spec` and `scripts/build-lite-bundle.ps1`
  deleted.
- `.github/workflows/release.yml`: matrix trimmed to `full` + `cli`,
  smoke test now expects `textual` to be present in the full bundle.

No backend, formlogic, or GUI behavior changes.
