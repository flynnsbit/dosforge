# dosforge v0.7.4 — installer fix

Hot-fix for `scripts/install.sh` shipped in v0.7.3.

## Bug

```
==> Discovering latest dosforge release on github.com/flynnsbit/dosforge...
Traceback (most recent call last):
  File "<string>", line 3, in <module>
    d = json.load(sys.stdin)
JSONDecodeError: Expecting value: line 1 column 1 (char 0)
```

The `say()` helper printed its messages to **stdout** instead of
**stderr**.  When `meta="$(get_release_metadata)"` captured the
function's stdout to feed it to the JSON parser, the captured
string contained both the `==> Querying...` say message AND the
JSON.  Python's `json.load` choked on the first `=` character.

## Fix

```diff
-say()   { printf '\033[1;36m==>\033[0m %s\n' "$*"; }
+say()   { printf '\033[1;36m==>\033[0m %s\n' "$*" >&2; }
```

`warn()` and `fatal()` were already correctly going to stderr; only
`say()` had the bug.

## Re-running the installer

The v0.7.3 installer still doesn't work for new users.  Run the
v0.7.4 installer instead:

```bash
curl -fsSL https://raw.githubusercontent.com/flynnsbit/dosforge/main/scripts/install.sh | bash
```

Anyone who already has v0.7.3 installed: nothing to do — the v0.7.3
release itself is identical to v0.7.4 minus the installer fix.
