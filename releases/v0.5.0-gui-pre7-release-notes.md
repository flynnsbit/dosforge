# dosforge v0.5.0-gui-pre7 — no more console flashes, with a live log panel

Two improvements aimed at the GUI's create-VHD experience:

## 1. Subprocess console windows no longer flash

The windowed `dosforge-gui.exe` has no attached console, so every
subprocess spawned for tools like `qemu-img.exe`, `mformat.exe`,
`mcopy.exe`, `mattrib.exe`, or `qemu-system-i386.exe` previously got
its own brand-new console window that flashed briefly on screen — once
per command, repeatedly during a single VHD build.

Every internal `subprocess.run` / `subprocess.Popen` call now passes
`creationflags=CREATE_NO_WINDOW` on Windows via a shared helper
(`dosforge.commands.subprocess_no_window_kwargs`). No more flashing.

## 2. Live log panel under the status bar

The GUI's status bar now has a "Show log" / "Hide log" toggle that
expands an inline log panel. The log panel automatically opens when
an operation starts and shows the backend's `print()` output line by
line — so you can watch `create-and-prepare` work its way through
preflight, partitioning, formatting, MBR write, and the QEMU SYS
install instead of staring at a "Working…" message and wondering
whether anything is happening.

Implementation: each operation's worker thread runs under
`contextlib.redirect_stdout(sink)` + `redirect_stderr(sink)`, where
`sink` queues lines for the main Tk thread. The status bar drains the
queue every poll tick and appends to the log Text widget.

No backend changes — only subprocess kwargs and GUI plumbing.
