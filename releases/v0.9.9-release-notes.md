# dosforge v0.9.9 — FreeDOS floppy SHELL drive fix

Fixes a long-standing FreeDOS 1.44 MiB floppy boot bug: the
on-disk `CONFIG.SYS` / `FDCONFIG.SYS` and `AUTOEXEC.BAT` /
`FDAUTO.BAT` were rewritten to reference `C:\` paths even when
the target was a floppy (drive A:), so the kernel printed:

```
- InitDiskno hard disks detected
Bad or missing Command Interpreter: C:\COMMAND.COM /E:512 /MSG /P
  Enter the full shell command line:
```

and dropped the user into the manual shell prompt because there
is no C: drive on a floppy boot.

Tag: `v0.9.9` — Linux + Windows artifacts are built and uploaded
by CI in a single workflow run.

## Symptom

`floppy-img/img-freedos-na-1440k-sysfmt-minimal-nopayload.img`
booted the FreeDOS kernel correctly in 86Box, but then halted at
the `Bad or missing Command Interpreter` prompt because
`CONFIG.SYS` contained `SHELL=C:\COMMAND.COM /E:512 /MSG /P`.

## Root cause

`normalize_freedos_config_sys()` and
`normalize_freedos_autoexec_bat()` in `src/dosforge/boot.py` were
hard-coded to the hard-disk install case — they always rewrote
the `SHELL=` line to `C:\COMMAND.COM` and always replaced `A:\`
references in `AUTOEXEC.BAT` with `C:\`. The normalizers ran the
same way for both VHD and IMG floppy targets, so the floppy ended
up with a hard-disk-only startup configuration.

The companion `_prepare_source_file()` / `_copy_system_files()` /
`make_floppy_bootable()` pipeline never threaded a "target drive"
hint down to the normalizers; FreeDOS floppy media just inherited
the HD-flavoured rewrite.

## What changed

### Backend (`src/dosforge/boot.py`)

- **`normalize_freedos_config_sys(text, *, target_drive="C")`** —
  the SHELL= rewrite now emits `<target_drive>:\COMMAND.COM`
  instead of always `C:\COMMAND.COM`. Default stays `C` so VHD
  builds are byte-identical to v0.9.8.
- **`normalize_freedos_autoexec_bat(text, *, target_drive="C")`**
  — the drive-letter substitution now rewrites the *other* drive
  letter into the target drive (so an HD-style `C:\FDOS\BIN`
  becomes `A:\FDOS\BIN` on a floppy, while the existing
  HD-target behaviour of folding `A:\` → `C:\` is preserved).
  The synthesized `SET DOSDIR=` / `SET PATH=` / `IF EXIST`
  additions also use the target drive.
- **`BootInstaller._prepare_source_file(..., target_drive="C")`**
  — accepts the drive hint and passes it to the FreeDOS
  normalizers via a small lambda wrapper.
- **`BootInstaller._copy_system_files(..., target_drive="C")`**
  — threads the drive hint through both `_prepare_source_file`
  call sites.
- **`BootInstaller.make_floppy_bootable()`** — now calls
  `_copy_system_files(..., target_drive="A")` so every FreeDOS
  floppy image gets `SHELL=A:\COMMAND.COM` + `A:\FDOS\` paths.

VHD builds (`make_partition_bootable` flow) continue to use the
default `target_drive="C"` and produce byte-identical output to
v0.9.8.

## How to verify

```bash
# Rebuild the failing floppy case and inspect the produced files
sudo -v && scripts/build-smoke-matrix.py \
    --filter 'img-freedos.*sysfmt'

# Confirm SHELL line + AUTOEXEC drive letters
mtype -i floppy-img/img-freedos-na-1440k-sysfmt-minimal-nopayload.img ::CONFIG.SYS
mtype -i floppy-img/img-freedos-na-1440k-sysfmt-minimal-nopayload.img ::AUTOEXEC.BAT

# Boot the floppy in 86Box with a Pentium-class profile.  The
# FreeDOS kernel should reach the C> ... no, A:\> prompt instead
# of the "Bad or missing Command Interpreter" wait state.
```
