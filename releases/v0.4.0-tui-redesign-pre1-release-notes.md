# dosforge v0.4.0-tui-redesign-pre1 — TUI wizard + tabs redesign (PRE-RELEASE)

> ⚠️ **Pre-release.** A UX-only redesign of the Textual TUI — no
> changes to disk creation, boot install, or any backend logic.
> Functionally equivalent to `v0.4.0-osr2-authentic-pre1`, just
> easier on the eyes and easier to navigate.

## Why this exists

The single-screen rainbow-button TUI from earlier `0.4.0-*` builds
shipped ~24 colored buttons on one form with no information
hierarchy. The "Mount" and "Unmount" buttons sat right next to each
other in the same warning-yellow palette, the Create form scrolled
off the bottom on smaller terminals, and the app didn't launch
maximized on Windows so the first impression was a half-clipped
form.

This release restructures the TUI around a tabbed layout with a
guided Create wizard.

## What's changed

### Layout: TabbedContent with 5 tabs (Ctrl+1..5)

| Tab | Contents |
|---|---|
| **✨ New Disk** | 4-step Create wizard (Media → Boot → Payload → Confirm) |
| **📁 Browse** | Directory tree + selected-image bar |
| **🔧 Image Tools** | List contents, extract, open with associated app |
| **🔌 Mounts** | Mount / unmount workflow |
| **⚙ Utilities** | Diagnostics + tip text |

A global selected-image strip sits above the tabs so the currently
focused image is always visible regardless of which tab you're on.

### Create flow: 4-step wizard with live summary

The Create form is split into 4 steps with `Back` / `Next` buttons:

1. **Media** — media type, machine target, path, size, format,
   floppy type
2. **Boot** — boot mode, FreeDOS source, DOS profile, IBM DOS
   version
3. **Payload** — boot-assets dir, custom payload dir, FreeDOS URL
4. **Confirm** — label, overwrite checkbox, **Create** button

A `● 1. Media    ✓ 2. Boot    ○ 3. Payload    ○ 4. Confirm`
progress indicator shows where you are. A live summary card on the
right of the wizard updates as you change values so you can review
the final command before stepping through.

A `⚡ Quick Create` shortcut on the wizard nav jumps straight to
step 4 if you already know what you want.

### Palette: blue primary, neutral secondary, red destructive

- `.btn-primary` (blue, bold) — the single primary action per step
  (`Next`, `Create`)
- `.btn-secondary` (subtle) — everything else (`Mount`, `List`,
  `Extract`, `Open`, `Diagnostics`, etc.)
- `.btn-destructive` (red) — `Unmount` only

This removes the warning-yellow / success-green / error-red mix
that previously made every button compete for attention.

### Windows: auto-maximize on launch

`cli.py` calls `ShowWindow(GetConsoleWindow(), SW_MAXIMIZE)` on
Windows before launching the TUI. Best-effort — works in conhost,
no-op in Windows Terminal (which uses a different hwnd model and
doesn't honor ShowWindow on its tab containers). On Linux it's a
no-op.

### Picker contract: explicit state instead of widget visibility

Internal refactor: `_is_boot_assets_picker_active()` now checks
`self.path_picker_target == "boot-assets"` instead of inspecting
the boot-assets row's `.display` property. The old behavior broke
in the wizard layout because per-widget `.display` doesn't reflect
"actually visible to user" once step containers gate ancestry.

## What's preserved

- **All 43 widget IDs** — every test in `tests/test_app_form.py`
  still passes against the new layout
- **All keyboard shortcuts** — Ctrl+C quit, etc.
- **`_sync_create_form_visibility()` logic** — unchanged, still
  drives per-widget show/hide based on `media-type` + `boot-mode`;
  now also triggers a summary refresh
- **All CLI behavior** — `dosforge create ...` works exactly as
  before; this release only touches the interactive TUI

## What's NOT changed since `v0.4.0-osr2-authentic-pre1`

- Disk creation pipeline (qemu-img, mtools, DOSBox-X)
- Boot install logic (all 11 boot modes including OSR2 with HIMEM
  / IFSHLP / DBLBUFF authentic staging from the previous release)
- Vendor binaries (DOSBox-X 2026.05.02, qemu-img, mtools, 7-Zip
  probe)
- Test suite — all 299 backend tests + 30 TUI tests still pass
  (1 TUI test updated for new explicit picker contract, 1 narrowed
  to step-1 alignment since cross-step alignment is meaningless
  in a wizard)

## How to test

1. Download `dosforge-0.4.0-tui-redesign-pre1-full-windows-x64.zip`
2. Unzip somewhere convenient
3. Run `dosforge.exe`
4. Verify:
   - Window maximizes on launch (conhost only; WT users will see
     the normal window size)
   - 5 tabs visible at top, **New Disk** selected
   - Wizard shows step 1 (Media) with progress indicator
   - Summary card on the right shows the initial form state
   - `Next: Boot →` advances to step 2
   - `← Back` returns to step 1
   - `Ctrl+2` jumps to Browse, `Ctrl+3` to Image Tools, etc.
   - Color palette: only `Next` / `Create` are blue/primary;
     `Mount` / `List` / `Extract` are neutral; `Unmount` is red

Then build a disk via the wizard to confirm the Create flow still
works end-to-end. Any of the OSR2 / FreeDOS / msdos33 modes is a
good smoke test.

## Compatibility / dependencies

Unchanged from `v0.4.0-osr2-authentic-pre1`:

- **Optional**: 7-Zip on host for OSR2 IFSHLP / DBLBUFF authentic
  files
- **Required**: nothing extra — all backend deps bundled

## Known limitations

- Windows Terminal (`wt.exe`) ignores ShowWindow on its tab
  containers — the app launches at the default tab size. Use
  conhost (`cmd.exe` host) for the auto-maximize behavior, or
  manually maximize WT.
- No mouse-driven wizard nav yet — use buttons or Tab/Enter
- The summary card is text-only; doesn't preview the resulting
  command line yet (could be added in a future iteration if useful)
