# dosforge 0.3.0 — Windows port complete

**Feature parity with Linux.** Windows-native PyInstaller bundle ships
QEMU + mtools + py7zr; no admin required for the create/browse path;
optional native VHD mount via `Mount-DiskImage` (requires admin
elevation).

## What's new

- **Single-file Windows launcher.** Extract the archive, run
  `.\dosforge` from the extracted folder. PowerShell autocompletes
  `.ps1` or `.bat`.
- **All 12 boot modes ship bootable VHDs on Windows:** FreeDOS,
  MS-DOS 7.1 (FAT32), MS-DOS 3.30/3.31/5.0/6.22, PC-DOS / PC-DOS 7.0,
  **PC-DOS 7.1 (FAT32)** ← new, Compaq DOS 3.31, IBM 8088 DOS 3.3/5.0.
- **Cross-platform image-content verbs:** `dosforge ls / cat / get
  / put / rm / mkdir <image>` — browse + extract + inject without
  mounting. Works against VHD/IMG/IMA/VFD/DSK/XDF.
- **Native VHD mount on Windows** via `Mount-DiskImage` (admin
  required). Without admin: clear elevation hint + the mtools verbs
  above as the no-admin alternative.
- **`.7z` and `.zip` auto-extraction.** Drop a WinWorldPC archive into
  `dosassets/<mode>/`, dosforge transparently unpacks it.
- **MartyPC Xebec / XT-IDE / JR-IDE machine targets** (geometry locks)
  + classic Phoenix/AMI BIOS Type N presets — all 127 entries.

## Installation

1. Download `dosforge-0.3.0-windows-x64.zip` from the assets below.
2. Extract anywhere (e.g. `C:\Projects\dosforge\`).
3. From that folder, run:
   ```powershell
   .\dosforge       # launches the Textual TUI in your terminal
   .\dosforge ls testimages\foo.vhd /
   .\dosforge create --media-type vhd --format fat32 --size 2G `
       --boot-mode pcdos71 --path C:\temp\pcdos71.vhd
   ```

## Quick CLI cheat sheet

```powershell
# Create a bootable FreeDOS FAT16 VHD (no admin)
.\dosforge create --media-type vhd --format fat16 --size 64M `
    --boot-mode freedos --freedos-source auto --path .\fdos.vhd

# Create a bootable PC-DOS 7.1 FAT32 VHD (requires admin for the
# in-QEMU FORMAT32 step? No — runs as current user.)
.\dosforge create --media-type vhd --format fat32 --size 2G `
    --boot-mode pcdos71 --boot-assets-path .\dosassets\pcdos71 `
    --dos-install-profile full --path .\pcdos71.vhd

# Browse a VHD (no mount, no admin)
.\dosforge ls .\pcdos71.vhd /
.\dosforge cat .\pcdos71.vhd /CONFIG.SYS

# Mount as a drive letter (requires admin elevation)
Start-Process powershell -Verb RunAs
# in the elevated shell:
cd C:\Projects\dosforge ; .\dosforge mount --path .\pcdos71.vhd
```

## Known constraints

- **Floppy IMG (`.img`/`.ima`) cannot be mounted natively on Windows.**
  `Mount-DiskImage` only handles `.vhd`/`.vhdx`/`.iso`. Use the mtools
  verbs for floppy IMGs.
- `dosforge mount` requires admin elevation on Windows because
  `Mount-DiskImage` loads the storage virtualization driver. The
  unprivileged `dosforge ls/cat/get/put/rm/mkdir` verbs cover most
  workflows.
- VHDs are created as fully-allocated (de-sparsed) on Windows. A 504
  MiB VHD takes ~30s to create; a 2 GiB VHD takes ~2 min on SSD. This
  is necessary for `Mount-DiskImage` (and several other Windows tools)
  to accept the file.
