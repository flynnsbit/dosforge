# dosforge v0.9.36

## Fix: FAT32 grow no longer falsely rejected over "cluster band" mismatch

User-reported bug in v0.9.35:

```
[ERROR] Grow failed: Grow target (134217728 bytes) requires a 4096-byte
cluster size, but the existing VHD uses 512-byte clusters.  dosforge
grow v1 cannot relay out cluster chains across band boundaries -- pick
a target size within the same band, or use 'dosforge create' to
rebuild from scratch.
```

Hit on every grow of a small FAT32 VHD because small FAT32 partitions
legally use 512-byte clusters, and any meaningful grow target lands in
a different mformat cluster band (≥4 KiB).

The check was misconceived.  It was protecting against an **Option A**
constraint (in-place FAT-table edit, where mismatched cluster size
means you'd need to rewrite every file's cluster chain).  The actual
implementation is **Option B**: extract every file via `mcopy` → build
fresh empty VHD via `DiskManager.create_and_prepare` → `mcopy` files
back into the new filesystem.  In Option B the old cluster size is
**completely irrelevant** because the old filesystem is thrown away.

### What changed

- **Removed** `_validate_cluster_band_match` — the constraint it
  enforced doesn't apply to Option-B grow.
- **Added** `_validate_extracted_payload_fits` — checks the
  actually-meaningful constraint: after extraction, will the user's
  files fit in the new partition?  Estimates host bytes + 8 KiB
  cluster slack per file vs. new partition size minus 5%
  filesystem overhead.  Refuses with:

  ```
  Extracted user-file payload (42,123,456 bytes estimated with
  cluster slack across 1234 files) won't fit in the 33,554,432-byte
  target (31,876,710 usable after filesystem overhead).  Pick a
  larger --new-size.
  ```

- **Moved** the validation from pre-extract (step 2) to post-extract
  (step 3) so it can use the real extracted file count.

### Verified end-to-end on Windows

| Scenario | Before v0.9.36 | After v0.9.36 |
|---|---|---|
| FreeDOS FAT32 64 M → 256 M (cluster: 512 B → 2 KiB) | ❌ Refused | ✅ ~17 s end-to-end |
| FreeDOS FAT32 32 M → 1 G (user's report) | ❌ Refused | ✅ Works |
| MSDOS622 FAT16 32 M → 128 M | ✅ Still works | ✅ Still works |
| MSDOS622 FAT16 32 M → oversized target | ✅ N/A | ✅ Friendly "won't fit" error |

### Files changed

- `src/dosforge/_grow_impl.py`:
  - Replaced `_validate_cluster_band_match` with
    `_validate_extracted_payload_fits` (different semantics:
    measures real extracted payload size against new partition
    capacity).
  - `perform_grow` updated docstring + moved the check from
    pre-extract (step 2) to post-extract (step 3).
- `tests/test_grow_impl.py`:
  - Removed `TestValidateClusterBand` (the function it tested no
    longer exists).
  - Added `TestValidateExtractedPayloadFits` with three cases:
    small-fits-in-large, oversized-rejected, cluster-slack
    accounting for many tiny files.

All 52 grow/inspect tests pass.
