# dosforge v0.9.42 — Linux TUI: fix `?` help button hover artifact

Patch release on top of v0.9.41.

## What was wrong

When mousing over the `?` help button on the Grow tab, a small
stair-step artifact (a sliver of the hover background) protruded
from the bottom-right of the button into the row gap.

## Root cause

Textual's `Button` widget has an implicit `border: tall`
(adds 2 cells of horizontal space), and our global `Button`
rule adds `padding: 0 2` (4 more cells). A 1-character label
like `?` therefore needs **1 + 6 = 7 cells minimum** to render
cleanly. We had forced `width: 5` / `max-width: 5`, which
clipped 2 cells of the border + hover background and left them
painting outside the button bounds on hover.

## Fix

Bumped `Button.grow-help-btn` from width 5 → width 7. The
hover background now stays fully inside the button rectangle.

* `#grow-btn` (Grow VHD) still renders at 14×3 — no change.
* `#grow-help-btn` (?) now renders at 7×3 — no clipping.

Verified headless via `App.run_test()`.

## Install

### Linux

```bash
curl -L -o /tmp/dosforge.tar.gz \
  https://github.com/flynnsbit/dosforge/releases/download/v0.9.42/dosforge-0.9.42-linux.tar.gz
tar -xzf /tmp/dosforge.tar.gz -C /tmp
cd /tmp/dosforge-0.9.42 && sudo ./install.sh
```

### Windows

Download `dosforge-0.9.42-windows-x64.zip` or
`dosforge-0.9.42-cli-windows-x64.zip`. The Windows GUI is
unaffected by this fix; version-lock convention ships matching
artifacts anyway.
