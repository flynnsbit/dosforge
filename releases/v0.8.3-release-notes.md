# dosforge v0.8.3

Audit-driven fixes: four more per-boot-mode UI restrictions that
previously only fired at Create-click time now surface live in the
size-cap snap + Next-button validation + geometry preview line.

## Audit findings

Five gaps were found between what `disk.py:_validate_create_request`
rejects and what the UI prevents. Four are fixed in v0.8.3 (the
fifth is a low-priority edge case left for later).

| # | Boot mode | Backend cap | v0.8.2 UI | v0.8.3 |
|---|---|---|---|---|
| 1 | MSDOS331 | 32 MiB (uint16 total_sectors_16) | none | **32 MiB** clamp |
| 2 | COMPAQ331 | 504 MiB (Compaq FORMAT FAT16B cap) | none | **504 MiB** clamp |
| 3 | IBM8088 + DOS50 | 504 MiB (`IBM_DOS50_MAX_BYTES`) | 32 MiB (too tight!) | **504 MiB** when DOS50 |
| 4 | FreeDOS + AUTO + FAT32 | rejected (auto bundle is FAT16 only) | none | rejected at **Next** |
| 5 | MFM + IDE controller + IMG + FAT32-with-MFM | rejected | none | _left for later_ |

## What changed

### `formlogic.py`

- `BootMode.MSDOS331` rule gains `max_mb=32`.
- `BootMode.COMPAQ331` rule gains `max_mb=504`.
- `BootMode.IBM8088` rule loses `max_mb=32` (was over-restrictive for
  DOS50). The cap is now driven dynamically by ibm_dos_version via
  the new `_state_aware_max_mb(state, rule, fmt)` helper.
- `_snap_size_for_boot_mode` + `validate_media_step` +
  `geometry_preview_text` all switch from `_effective_max_mb(rule, fmt)`
  to `_state_aware_max_mb(state, rule, fmt)` so IBM8088 + DOS50
  builds get 504 MiB headroom instead of being clamped to 32 MiB.
- `validate_media_step` adds an explicit gate for
  FreeDOS + AUTO + FAT32 with a clear remediation message
  ("switch FreeDOS source to 'Local FreeDOS assets'").
- `coerce_on_ibm_version_change` now re-snaps the size after
  bumping the IBM DOS version, so flipping DOS50 → DOS33 clamps a
  200 MiB build down to 32 MiB live.

### Live preview

The geometry preview line now reflects the dynamic cap:

```
IBM 8088 + DOS33:  -> 32 MB ... (max 32M for fat16)
IBM 8088 + DOS50:  -> 504 MB ... (max 504M for fat16)
COMPAQ331:         -> 504 MB ... (max 504M for fat16)
MSDOS331:          -> 32 MB ... (max 32M for fat16)
FreeDOS FAT16:     -> 2048 MB ... (max 2G for fat16)
FreeDOS FAT32:     -> ... ... (max 2048G for fat32)
```

## What didn't change

- Backend `_validate_create_request` stays as defense in depth.
- `validate_size_for_ibm_dos`, `IBM_DOS33_MAX_BYTES`,
  `IBM_DOS50_MAX_BYTES`, `MSDOS331_MAX_BYTES`,
  `COMPAQ331_MAX_BYTES` constants in `size.py` unchanged.
- `CreateRequest` API + CLI flags unchanged.
- No new tests broken; existing per-mode-cap tests continue to
  enforce the tighter limits.

## Tests

189/189 focused tests pass — 8 new tests added:

- MSDOS331 cap 100M → 32M + validate rejects
- COMPAQ331 cap 1G → 504M
- COMPAQ331 400M (under cap) untouched
- FreeDOS AUTO + FAT32 → rejected at validate_media_step
- FreeDOS LOCAL + FAT32 → allowed
- IBM8088 + DOS33 + 100M → 32M (unchanged behavior)
- IBM8088 + DOS50 + 1G → 504M (NEW headroom)
- IBM8088 version flip DOS50 → DOS33 re-snaps 200M → 32M
