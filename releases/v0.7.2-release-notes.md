# dosforge v0.7.2

Two changes:

1. **New boot mode: IBM PC-DOS 3.00 (`pcdos3`)** — the IBM-branded
   sibling of MS-DOS 3.0, released August 1984 with the IBM PC AT.
   First DOS in dosforge's HDD-bootable lineup that doesn't need
   Compaq-specific BIOS extensions (it has `BPB.hidden_sectors`
   from DOS 3.0).

2. **Consolidated release model: ONE release per version.** Linux
   and Windows builds now share a single `v<X.Y.Z>` tag and upload
   their assets to the same GitHub release. Previous separate
   `linux-v<X.Y.Z>` + `windows-v<X.Y.Z>` releases are kept as
   historical artifacts; new releases use `v<X.Y.Z>` only.

## New: `--boot-mode pcdos3`

```powershell
# Floppy IMG (1984-authentic 360k DSDD)
.\dosforge create --media-type img --boot-mode pcdos3 ^
    --format fat12 --floppy-type 360k --img-system-format ^
    --path C:\my-floppies\pcdos3.img

# MFM hard-disk VHD (ST-225 10 MiB, FAT12, IBM AT-class)
.\dosforge create --media-type vhd --boot-mode pcdos3 ^
    --format fat12 ^
    --disk-controller mfm --bios-drive-type phoenix:1 ^
    --path C:\my-vhds\pcdos3-mfm.vhd
```

Source media: `dosassets/pcdos3/IBM PC-DOS 3.00 (5.25).7z` (4.1 MB
WinWorldPC archive — auto-extracted on first build) or pre-extracted
`Disk01.img`.

**Constraints:**
- FAT12 only (FAT16 was added in PC-DOS 3.10)
- Max partition: ~16 MiB
- IBM-style system file naming (IBMBIO.COM / IBMDOS.COM)
- Works on both IDE and MFM controllers (auto-defaults to MFM
  for 1984-authentic IBM PC AT emulation)
- Files dated 1984-07-05 (IBMBIO/IBMDOS) and 1984-08-14 (COMMAND.COM
  and tools)

**Live-verified:**
- Floppy IMG: 360 KB, IBMBIO/IBMDOS hidden+system + 36 standard
  utilities
- MFM VHD: 10.2 MiB, footer CHS 306×4×17 (ST-225 / Phoenix Type 1),
  partition FAT12 type 0x01 at LBA 17, track-aligned

## Consolidated release model

### Before v0.7.2

Each version produced TWO GitHub releases:
- `linux-v0.7.1` — Linux tarball + wheel + sdist
- `windows-v0.7.1` — Windows zip (full + cli)

Two tags, two release pages, two sets of release notes
(`releases/{linux,windows}-v0.7.1-release-notes.md`).

### v0.7.2 and forward

ONE GitHub release per version with all assets:
- Tag: `v0.7.2`
- Release: `dosforge 0.7.2`
- Assets attached:
  * `dosforge-0.7.2-linux.tar.gz` (Linux bundle)
  * `dosforge-0.7.2-py3-none-any.whl` (Linux wheel)
  * `dosforge-0.7.2.tar.gz` (Linux sdist)
  * `dosforge-0.7.2-windows-x64.zip` (Windows full bundle)
  * `dosforge-0.7.2-cli-windows-x64.zip` (Windows CLI-only)
- One release-notes file: `releases/v<X.Y.Z>-release-notes.md`

### Workflow changes

Both `.github/workflows/release-linux.yml` and
`.github/workflows/release.yml` now:
- Trigger on `v[0-9]+.[0-9]+.[0-9]+` (was `linux-v*` / `windows-v*`)
- Use an idempotent `gh release view || gh release create` pattern
  so whichever workflow runs first creates the release, and the
  others upload to it
- Look for `releases/v<X.Y.Z>-release-notes.md` (single file)
- Upload to the same `v<X.Y.Z>` tag with `--clobber`

### Migration for users

No action required for end users — just look at the latest
release at https://github.com/flynnsbit/dosforge/releases/latest
and grab the asset that matches your platform.

### Migration for contributors / release engineers

Releases are now tagged with `v<X.Y.Z>` (not `linux-v<X.Y.Z>` /
`windows-v<X.Y.Z>`).  Push **one** tag per version:

```bash
git tag -a v0.7.2 -m "v0.7.2"
git push origin v0.7.2
```

Both Linux and Windows CI workflows trigger on the same tag and
publish their assets to the same release.
