# dosforge v0.9.17

Bug fix: builds that need to scrub files from the install floppy
(DR-DOS 6, possibly others) no longer abort with
`FAILED: Missing external command: mdeltree`.

## Root cause

`legacy_dos_install._prepare_install_floppy` called `mdeltree` to
recursively delete entries from the scratch install floppy before
launching QEMU.  `mdeltree` was removed from modern mtools builds
(including the dosforge Windows vendor bundle which ships only
`mattrib`, `mcopy`, `mdel`, `mdir`, `mformat`, `mmd`, `mtype`).

The runner's `check=False` flag only suppresses non-zero exit
codes; it does **not** suppress `DependencyError` raised when the
binary itself is missing.  So the very first `mdeltree` invocation
aborted the build with the error shown in the screenshot.

## Fix

`_prepare_install_floppy` now wraps the `mdeltree` call in
`try / except DependencyError`.  When `mdeltree` is unavailable,
the build falls straight through to the subsequent `mdel` call
which handles files (the common case in `pre_install_deletes`).
Any leftover directories on the install floppy waste a few KB but
don't block the install.

## Affected boot modes

`drdos6` was the boot mode that hit the regression in the
screenshot.  Other boot modes whose profiles set
`pre_install_deletes` (`pcdos71`, `drdos7`, etc.) get the same
fix transparently.

## Tests

Existing focused tests pass.  The 9 skipped tests in
`test_legacy_dos_install.py` are gated on a real QEMU + install
media -- skipping continues to be normal in the test env.

## Files changed

- `src/dosforge/legacy_dos_install.py` -- import
  `DependencyError`; wrap `mdeltree` invocation in
  `try / except DependencyError` in `_prepare_install_floppy`.
