# dosforge v0.9.38

## Windows GUI feature parity with Linux TUI (Grow VHD)

User feedback after v0.9.37 (which fixed FreeDOS FAT32 boot on
Linux): *"windows still has the boot mode list and a missing mcopy
command when trying to run it error. make the windows gui on
feature parity with the linux version."*

This release brings the Windows Tk GUI's **Grow VHD** tab to full
feature parity with the Linux TUI introduced in v0.9.34 / v0.9.35.

### Fix 1 — `mcopy` missing on Windows during Grow

`src/dosforge/_grow_impl.py:run_grow` and
`src/dosforge/inspect.py:_present_system_files` were both
constructing `CommandRunner()` directly with **no `tool_resolver`**.
On Windows that meant `mcopy` / `mdir` / `mformat` / `mattrib` /
`mmd` were passed as bare names to `subprocess.run`. The bundled
`vendor/windows/bin/mcopy.exe` (and friends) is NOT on `PATH`, so
the runner failed with:

```
DependencyError: Missing external command: mcopy
```

Both call sites now build the runner via
`runner_for_backend(get_backend())` — the same helper that
`DiskManager` uses — so bare tool names are routed through
`WindowsBackend.tool_path` and resolved to the bundled absolute
paths. `dosforge grow` and the GUI's auto-infer (which inspects
the source VHD on selection) now both work cleanly on Windows.

### Fix 2 — Remove boot-mode dropdown from the GUI Grow tab

The Linux TUI dropped the boot-mode `Select` in v0.9.35 (the
backend auto-detects from `KERNEL.SYS` / `IBMBIO.COM` / `[Paths]`
MSDOS.SYS at run time) but the Windows GUI still required the user
to pick from a `Combobox`. The tab now:

* Drops the `Boot mode:` row entirely.
* Builds `GrowManifest(..., boot_mode=None)` so the backend
  auto-detects the same way the CLI / TUI do.
* Renames the *"Refresh inferred boot mode"* button to
  *"Refresh VHD info"* (the inferred mode is still shown in the
  metadata line — it just isn't required input anymore).

### Fix 3 — Per-step progress in the Grow output panel

The TUI streams 8 stage transitions through `progress_callback`
(snapshot / validate / extract / build / inject / stage / probe /
swap) so users can see which step is consuming wall-clock. The Tk
GUI now passes the same callback into `grow_vhd()` — each message
is `print()`-ed inside the worker thread, captured by the GUI's
`_LogStream`, and rendered live into the status log + the
operation-output Text widget.

Also: the boot-probe checkbox label now matches the TUI:

> *"Headless boot probe (verify the grown VHD boots before swap;
> adds ~60–90s)"*

…so the wall-clock cost is visible at-a-glance.

### Verification

* Targeted suite green (`test_grow_impl`, `test_grow_manifest`,
  `test_inspect`, `test_core_modules`): **68 passed in 2.59s**.
* `grow_view.py` static checks: no `_GROW_BOOT_MODE_OPTIONS`,
  `var_boot_mode`, `_boot_mode_label_to_value`, or
  `GROWABLE_BOOT_MODES` references survive; `progress_callback`
  wiring + `boot_mode=None` + renamed button + new probe label
  all present.
* `dosforge._gui.grow_view` imports cleanly.

### Install one-liners

**Linux:**

```bash
curl -fsSL https://github.com/flynnsbit/dosforge/releases/download/v0.9.38/dosforge-0.9.38-linux.tar.gz \
  | tar xz
./dosforge-0.9.38-linux/install.sh
```

**Windows (full GUI + CLI bundle):** download
`dosforge-0.9.38-windows-x64.zip` from the release page and
extract anywhere; run `dosforge-gui.exe`.

**Windows (CLI only):** download
`dosforge-0.9.38-cli-windows-x64.zip` from the release page and
extract anywhere; run `dosforge.exe --help`.
