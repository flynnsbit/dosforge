# dosforge v0.9.31

## Bigger, scrollable, copyable status log (TUI + GUI)

The bottom-of-screen status panel was previously a 3-line non-scrollable
`Static` widget that overwrote itself on every status update.  Long
messages got truncated, past results were unrecoverable, and there was
no way to grab the contents for a bug report.

### TUI (Linux)

- **Log panel grew from 3 lines to ~5 visible content lines** (7 total
  including the bordered chrome).
- **Persistent scrollback** — every status message is appended to a
  `RichLog` widget (capped at 500 lines) instead of overwriting.  The
  panel scrolls automatically; use the mouse wheel or PageUp/PageDown
  to browse history.
- **New `Ctrl+Y` binding -- "Copy log"** — pushes the full log to the
  system clipboard via the terminal's OSC 52 escape sequence.  Works
  over SSH and inside tmux (provided the terminal emulator supports
  OSC 52, which all modern ones do).
- **New `Ctrl+Shift+L` binding -- "Clear log"** — wipes the persistent
  log when you want a fresh start.
- The animated spinner ("⠋ Working on ... [3.4s]") now writes to a
  dedicated single-line status row *above* the log so high-frequency
  spinner ticks don't drown out the message history.

### GUI (Windows / Linux)

- **New "Copy log" button** next to the existing "Show log" toggle in
  the bottom status bar.  Copies the entire log buffer (already capped
  at 500 lines by `append_log`'s ring-buffer trim) to the OS clipboard
  via Tk's clipboard bridge.
- The 8-line scrollable log panel already supported scrolling and
  manual text selection; only the convenience button is new.

### Files touched

- `src/dosforge/app.py` -- swap `#status` `Static` for `RichLog`, add
  `#status-current` spinner row, wire `action_copy_log` + `action_clear_log`,
  maintain `_status_log_history` mirror so copy returns raw text.
- `src/dosforge/_gui/widgets.py` -- add `_copy_btn` + `copy_log_to_clipboard`
  method on `StatusBar`.

### Compatibility

No public API changes.  Existing `DosForgeApp._set_status` /
`_clear_status` call sites continue to work unchanged.
