# dosforge v0.3.2 — minimum CLI-only Windows bundle

This release adds a third Windows asset variant for users who want the
smallest possible footprint and don't need the TUI or the 3 boot modes
that drive QEMU's i386 emulator.

## New asset: `dosforge-0.3.2-cli-windows-x64.zip`

| Bundle | Zipped | Unzipped | TUI | Boot modes |
|---|---|---|---|---|
| Full (`-windows-x64.zip`) | ~132 MB | ~380 MB | yes | all 11 |
| Lite (`-lite-windows-x64.zip`) | ~127 MB | ~313 MB | yes | all 11 |
| **CLI (`-cli-windows-x64.zip`)** | **~27 MB** | **~64 MB** | **no** | **8 of 11** |

## What's stripped from the CLI bundle

We measured the PE-import transitive closure of every binary in
`vendor/windows/bin/` and discovered most of it is reachable only from
`qemu-system-i386.exe`:

| Layer | Size | Status in CLI bundle |
|---|---|---|
| Python runtime + dosforge source | ~25 MB | kept |
| `qemu-img.exe` + 7 mtools binaries + 28 transitive DLLs | ~25 MB | kept |
| `qemu-system-i386.exe` + 80 GTK/SDL/codec DLLs | ~135 MB | **stripped** |
| 17 orphan files (Vulkan, swiftshader, unused BIOS ROMs) | ~33 MB | **stripped** |
| TUI stack (textual, rich, markdown_it, pygments, psutil) | ~43 MB | **stripped** |
| py7zr stack (Cryptodome, pyppmd, pyzstd, brotli, etc.) | ~10 MB | **stripped** |

## What this affects

### Works in CLI bundle (8 boot modes + all infrastructure)
- All `create` subcommands for `--media-type vhd` and `--media-type img`
- Boot modes: `none`, `freedos`, `msdos5`, `msdos622`, `msdos71`,
  `pcdos7`, `pcdos71`, `ibmpcdos401`, `ibm8088`
- `list-mounts`, `list-martypc-formats`, `list-bios-drive-types`
- `ls`, `cat`, `get`, `put`, `rm`, `mkdir` (image content verbs)
- `check-deps`, `sudo-check`
- Native Windows VHD mount via `Mount-DiskImage` (admin only)
- `.zip` archive auto-extraction (stdlib `zipfile`)

### Doesn't work in CLI bundle (the trade-off)
- `dosforge tui` — prints existing fallback ("textual not available")
- Boot modes `compaq331`, `msdos33`, `msdos331` — these require booting
  the install media in QEMU to run `SYS C:`. The CLI bundle's
  dependency check produces a clean "Missing required tools:
  qemu-system-i386" error. Install the lite or full bundle for these.
- `.7z` archive auto-extraction (use Windows Explorer / 7-Zip to extract
  manually, then point dosforge at the resulting directory)

## Which one to pick?

| You want... | Use |
|---|---|
| TUI + every boot mode + bundled DOS install media | Full |
| TUI + every boot mode + bring your own install media | Lite |
| Smallest CLI footprint + modern boot modes only | **CLI** |

## Verified

- All 299 unit tests still pass
- CLI bundle: `dosforge.exe --help` works, `dosforge.exe tui` shows the
  expected error, `dosforge.exe create --media-type vhd --size 32M --path test.vhd`
  produces a working 32 MB non-bootable VHD
- CI smoke-test gate refuses to publish a CLI bundle that accidentally
  bundles `textual` or `qemu-system-i386.exe`
