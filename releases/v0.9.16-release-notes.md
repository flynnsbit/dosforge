# dosforge v0.9.16

GUI cosmetic: swap the `Boot` and `Output` cards so `Boot` comes
first.

## Before (v0.9.15)
```
Output           ← Output image path / Volume label / Overwrite
Boot             ← Boot OS, Boot assets, FreeDOS source, ...
Media & geometry ← Media type, Disk controller, Geometry source, ...
Payload          ← Custom payload, FreeDOS URL
Summary
```

## After (v0.9.16)
```
Boot             ← MOVED UP -- pick the OS first
Output           ← then choose where to write it
Media & geometry
Payload
Summary
```

Matches the natural decision flow ("pick what OS I want, then say
where to put it") and aligns with the TUI wizard which already
walks the user through Boot OS -> Output path in that order.

## What didn't change

- All card contents -- only their stacking order in the scrollable
  form swapped.
- Snap rules, validation, field IDs, formlogic -- identical.
- The TUI -- it was already Boot first via the wizard.

## Tests

All focused tests still pass (layout-only change).

## Files changed

- `src/dosforge/_gui/create_view.py` -- swap order of `out_card`
  and `boot_card` in `_build`.
