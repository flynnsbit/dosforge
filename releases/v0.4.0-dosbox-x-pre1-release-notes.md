# dosforge v0.4.0-dosbox-x-pre1 — DOSBox-X swap (PRE-RELEASE)

> ⚠️ **Pre-release.** This is a feature-branch build that replaces
> `qemu-system-i386` with **DOSBox-X** for the 3 legacy DOS install
> modes (`compaq331`, `msdos33`, `msdos331`). End-to-end install of a
> real install diskette in DOSBox-X has NOT been validated yet —
> please test before relying on this build for legacy DOS modes.
> Main / v0.3.2 is unaffected and remains the stable release.

## Why this exists

A PE-import transitive closure analysis of `vendor/windows/bin/`
revealed that `qemu-system-i386.exe` drags in **80 DLLs totalling
~110 MB** of GTK / SDL / codec / Spice / virgl / USB / NSS bloat
(plus 17 orphan files = another ~33 MB). All of it is required at
Windows process load time even though our actual invocation
(`-display none -nic none`) uses none of it.

Empirically verified: only ~2 MB is droppable from the stock MSYS2
build without breaking the PE loader.

**Solution:** swap qemu-system-i386 for **DOSBox-X** (purpose-built
for installing DOS into disk images via `IMGMOUNT C: -fs none` +
`BOOT A:` + scripted `SYS C:`). DOSBox-X ships as a single
self-contained 24 MB statically-linked EXE.

## Measured size impact

| Variant | v0.3.2 (main) | This pre-release |
|---|---|---|
| Full | 126 MB zipped | **108 MB** |
| Lite | 122 MB zipped | **50 MB** ⭐ |
| CLI | 27 MB zipped (8 modes) | **38 MB (all 11 modes)** |

The CLI variant grew slightly (added 24 MB DOSBox-X) but **regained
the 3 legacy DOS boot modes it lost in v0.3.2**. Lite/full shrank by
~70 MB / ~18 MB zipped respectively.

## What changed

- `vendor/windows/manifest.json` — DOSBox-X v2026.05.02 component
  (single 24 MB self-contained EXE, GPL-2.0)
- `src/dosforge/legacy_dos_dosboxx_install.py` — DOSBox-X driver that
  re-uses the QEMU installer's floppy-prep + verify logic, generates
  an IMGMOUNT `.conf`, runs `dosbox-x.exe -conf -fastlaunch -exit`
- `src/dosforge/_platform/{base,windows}.py` — new
  `legacy_dos_emulator()` method auto-picks `"dosbox-x"` when the EXE
  is bundled, falls back to `"qemu"` otherwise
- `src/dosforge/disk.py` — dispatches to the right installer
- `windows/vendor_allowlist.py` — shared 37-file allowlist
  (qemu-img + 7 mtools + 28 DLLs + dosbox-x) used by all 3 specs
- All three PyInstaller specs filter vendor inputs through the
  allowlist — qemu-system + its 110 MB DLL stack are excluded
  everywhere
- CI smoke-test asserts no variant ships qemu-system and DOSBox-X is
  present in every variant
- 7 new unit tests in `tests/test_dosbox_x_install.py`

## What works (verified)

- All 299 existing unit tests pass + 6 new DOSBox-X tests
- Backend correctly picks DOSBox-X on Windows when bundled
- All 3 bundles build, smoke-test, and zip successfully
- `dosforge create` for non-bootable VHDs (qemu-img + mtools path —
  unchanged from v0.3.2)
- TUI launches correctly in lite/full variants

## What needs validation (please test before relying on this)

- **End-to-end SYS install via DOSBox-X** for compaq331 / msdos33 /
  msdos331 boot modes. The unit tests verify the `.conf` shape and
  dispatch logic; only a live install can confirm DOSBox-X's
  `IMGMOUNT C: -fs none` + `BOOT A:` + scripted `SYS C:` produces a
  bootable VHD with the right BPB.
- 86Box boot of the resulting VHD after a legacy DOS install

If any legacy mode breaks, please file an issue with the DOSBox-X
log (default path: `$env:USERPROFILE\AppData\Local\dosforge\cache\
legacy-dos-install\dosbox-x-*.log`).

## How to test

1. Download `dosforge-0.4.0-dosbox-x-pre1-lite-windows-x64.zip` (or
   full/cli)
2. Unzip + drop your DOS install diskette in `dosassets\<mode>\`
3. Run `dosforge create --media-type vhd --boot-mode compaq331
   --size 32M --path test-compaq.vhd`
4. Verify the resulting VHD boots in 86Box / MartyPC
