# dosforge v0.6.3 — GUI parity for the PC-DOS 7.1 SGTK fetcher

Follow-up to v0.6.2.  The desktop GUI (the same one shipped to
Windows as `dosforge-gui.exe` and used on Linux as the default
front-end) now has a **Fetch PC-DOS 7.1 (SGTK) assets** button on
the New Disk view — the GUI equivalent of the TUI's pre-fetcher
button.

## What's new

When the boot mode is set to **PC-DOS 7.1**, the New Disk view
exposes a new button under the *Boot* card:

> **Fetch PC-DOS 7.1 (SGTK) assets**

Clicking it runs the same `fetch_pcdos71_assets()` pipeline the TUI
uses:

1. Downloads and extracts the IBM ServerGuide Scripting Toolkit
   (SGTK 1.3.07) from archive.org via 7-Zip.
2. Stages the 40 authentic PC-DOS 7.10 system files into
   `dosassets/pcdos71/`.
3. If `dosassets/pcdos2000/<IBM PC-DOS 2000 ...>.7z` is also
   present, expands the IBM FTCOMP pack files via DOSBox-X +
   `UNPACK2.EXE` and merges the resulting utilities (EMM386, POWER,
   DOSSHELL, DEFRAG, BACKUP, RESTORE, SETVER, UNDELETE, HELP,
   PRINT, REPLACE, SHARE, INTERLNK, INTERSVR, ANSI.SYS, EGA.SYS,
   DRIVER.SYS, ...) into `dosassets/pcdos71/DOS/`, **SGTK winning
   every filename conflict**.
4. Auto-fills the *Boot assets* field with the staged target dir.

Progress reporting:

- Each stage label streams into the GUI log panel via stdout
  (the worker thread captures stdout/stderr for the lifetime of
  every operation and feeds it into the StatusBar).
- The final status line reports the SGTK file count plus, when
  hydration ran, `… plus N extra utilities from <archive> (M kept
  SGTK)`, mirroring the TUI's success message exactly.
- Hydration failures (missing archive, missing `dosbox-x`/`7z`,
  DOSBox-X crash) are caught and reported as `; PC-DOS 2000
  hydration skipped: <reason>` — the SGTK install still succeeds.

The button is only shown when the **PC-DOS 7.1** boot mode is
selected.  Other DOS modes (MS-DOS 5 / 6.22 / 7.1, IBM 8088,
Compaq 3.31, PC-DOS 2/3/5/6/7, etc.) keep their existing controls
unchanged.

## Notes

- Tested end-to-end against the real WinWorldPC archive: SGTK
  fetch + PC-DOS 2000 hydration produces a 138-file `C:\DOS\`
  identical to the TUI's output.
- `formlogic.py` gains a new `FIELD_FETCH_PCDOS71 =
  "fetch-pcdos71-btn"` constant and a visibility rule
  (`show_dos_profile and boot_mode is BootMode.PCDOS71`).  Two new
  test cases in `tests/test_formlogic.py` exercise the rule.
- This is a Linux release of the same code that gets packaged into
  the Windows `dosforge-gui.exe`.  Windows users will get the new
  button next time the Windows bundle is rebuilt from this commit.

## Upgrading

```bash
cd releases/v0.6.3
chmod +x install.sh
./install.sh
```

Safe to re-run over v0.6.2 — just refreshes the wheel +
`dosassets/` + desktop entry.

To unlock the PC-DOS 2000 hydration leg of the new button, drop
the WinWorldPC archive into `dosassets/pcdos2000/` (e.g.
`dosassets/pcdos2000/IBM PC-DOS 2000 (3.5-1.44mb).7z`).  The
archive stays in your gitignored local copy and is never shipped.
