# dosforge v0.9.13

Two more legacy DOS family floppy IMG paths land: **MS-DOS 7.10
(OSR2)** and **IBM PC-DOS 2000** can now be produced as bootable
1.44 MiB floppies via the verbatim-Disk-1 copy path (same pattern
as v0.9.11/v0.9.12 DR-DOS 6/7). The smoke matrix script also
stops over-skipping `pcdos3` and `compaq3` IMG cases — their
backend path has been wired for a while; the script was the
holdout.

## What landed

- **MSDOS71 IMG (`img-msdos71-na-1440k-sysfmt-...`)** — verbatim
  copy of the OSR2 boot floppy (`dosassets/msdos71/disk01.img`).
  Carries `IO.SYS`/`MSDOS.SYS`/`COMMAND.COM` + the OSR2 utility
  set (`ATTR`, `DELTREE`, `GDISK`, `FIND`, `DOSKEY`, `MCD`,
  `PKUNZIP`, `XMSDSK`, `HIMEM`, `CTMOUSE`, `BOOTPART`). The OEM
  `AUTOEXEC.BAT` (which chained through CTMOUSE/MSCDEX and ran
  `SETUP.BAT`) is replaced with a minimal `@ECHO OFF` +
  `PROMPT $p$g`, so the floppy boots to `A:\>` instead of trying
  to install Win95 OSR2. `SETUP.BAT`/`SETUP.INF` are left on
  disk for users who want to run setup manually.
- **PCDOS2000 IMG (`img-pcdos2000-na-1440k-sysfmt-...`)** —
  verbatim copy of `dosassets/pcdos2000/IBM PC-DOS 2000 (3.5-1.44mb).7z`
  Disk 1 (auto-extracted on demand via py7zr).  Carries
  `IBMBIO.COM`/`IBMDOS.COM`/`COMMAND.COM` + the PC-DOS 2000
  utility set (`ATTRIB`, `CHKDSK`, `CHOICE`, `DEBUG`, `DISKCOPY`,
  `FDISK`, `FORMAT`, `KEYB`, …).  The stock `AUTOEXEC.BAT`
  (which ran `CHOICE /C:YN /TY,10 Do you want to install PC DOS
  7.0` then `setup`) is replaced with the same minimal stub.
- **PCDOS3 + COMPAQ3 IMG** — already worked at the backend layer
  (both have been in `verbatim_floppy_modes` since v0.9.6), but
  `scripts/build-smoke-matrix.py` was still over-skipping them
  with "IMG floppy build path is not implemented". The script
  now only skips on truly-missing dispatchers (MSDOS6, the
  generic PCDOS catch-all, and 4DOS).
- **MSDOS71 IMG asset-availability probe** added to
  `_REQUIRED_ASSET_GLOBS` so the smoke matrix skips with
  "Local install media missing" instead of producing a FAIL log
  when `dosassets/msdos71/disk01.img` isn't present.

## Internal changes

- `src/dosforge/disk.py`
  - `verbatim_floppy_modes` extended with `BootMode.MSDOS71`
    and `BootMode.PCDOS2000` (both F1440K).
  - MSDOS71 verbatim path overrides
    `descriptor.asset_fallback_dirs` to `("msdos71",)` so it
    picks the user's OSR2 boot floppy at
    `dosassets/msdos71/disk01.img` instead of the Win95 SETUP
    floppy at `dosassets/w95/Disk01.img` (which is the
    `MINI.CAB`/`PRECOPY1.CAB` cabinet-staging disk, not
    bootable).  The VHD QEMU pipeline continues to use the
    descriptor's full `("w95", "msdos71")` fallback chain.
  - `_sanitize_verbatim_install_floppy` membership widened from
    `{DRDOS7}` to `{DRDOS7, MSDOS71, PCDOS2000}`. The sanitizer
    only replaces `AUTOEXEC.BAT`; OEM installer binaries
    (`INSTALL.EXE`, `SETUP.BAT`, `SETUP.EXE`) stay on the disk
    so users can run them manually.
- `scripts/build-smoke-matrix.py`
  - `_IMG_UNSUPPORTED_MODES` reduced from
    `{MSDOS6, MSDOS71, PCDOS, PCDOS2000, PCDOS3, COMPAQ3, FOURDOS}`
    to `{MSDOS6, PCDOS, FOURDOS}`.
  - `_REQUIRED_ASSET_GLOBS` gains a `BootMode.MSDOS71` entry
    pointing at `msdos71/disk01.img` and the WinWorldPC `.7z`/
    `.zip` archive forms.

## Tests

- `tests/test_disk_nbd.py::test_create_img_msdos71_dispatches_to_verbatim_copy_path`
  replaces the old
  `test_create_img_system_format_aligns_msdos71_with_install_image_size`,
  asserting:
  - the resolver + installer are never invoked for MSDOS71 IMG,
  - non-`F1440K` floppy types are rejected with the
    "requires `--floppy-type 1440k`" message.

Full targeted sweep (213 tests):

```
pytest -q tests/test_disk_validation.py tests/test_disk_nbd.py \
  tests/test_formlogic.py tests/test_legacy_dos_install.py \
  tests/test_e2e_matrix.py tests/test_cli.py
```

End-to-end verification of MSDOS71/PCDOS2000/DRDOS6/DRDOS7 IMG
builds was performed via direct `DiskManager.create_and_prepare`
invocation; the produced floppies were inspected with `mtype` /
`mdir` to confirm authentic upstream content + sanitized
`AUTOEXEC.BAT`.

## Smoke matrix expectations

Re-running `scripts/build-smoke-matrix.py` on v0.9.13 should
flip the four previously-skipped IMG cases from
`SKIP (IMG floppy build path is not implemented)` to either
`PASS` (when the install media is present in `dosassets/<mode>/`)
or `SKIP (Local install media missing -- drop a WinWorldPC/IBM
archive into dosassets/<mode>/)` (when it isn't):

| Case                                              | Before (v0.9.12) | After (v0.9.13)             |
|---------------------------------------------------|------------------|------------------------------|
| `img-msdos71-na-1440k-sysfmt-minimal-nopayload`   | SKIP (not impl.) | PASS (media on dev box)      |
| `img-pcdos2000-na-1440k-sysfmt-minimal-nopayload` | SKIP (not impl.) | PASS (media on dev box)      |
| `img-pcdos3-na-360k-sysfmt-minimal-nopayload`     | SKIP (not impl.) | SKIP-asset (no media on box) |
| `img-compaq3-na-360k-sysfmt-minimal-nopayload`    | SKIP (not impl.) | SKIP-asset (no media on box) |

## What did not change

- VHD pipelines for MSDOS71/PCDOS2000 are byte-identical to
  v0.9.12. The verbatim IMG path runs only when
  `MediaType.IMG` is requested; QEMU-driven hard-disk installs
  are untouched.
- MSDOS6 / generic PCDOS / 4DOS IMG paths remain unimplemented
  (no descriptor or shell-overlay code path). Future work.
