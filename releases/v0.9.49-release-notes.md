# dosforge 0.9.49 — MartyPC-Xebec preset auto-defaults to FAT12

Quality-of-life fix on top of v0.9.48.

## What's new

Picking any `martypc-xebec:N` BIOS preset (in TUI or GUI) now
auto-defaults the **Filesystem** field to FAT12.  Without this,
selecting `martypc-xebec:1` (10 MiB) and leaving the format on
FAT16 produced a confusing "FAT16 images must be at least 16 MiB"
error at Create-click time.

The 20 MiB Types 2/13/16 also default to FAT12 (matching the
1980s-era DOS 2.x/3.x they pair with); user can still flip the
format dropdown to FAT16 manually for those.

## Implementation

- New `formlogic.coerce_on_bios_drive_change(state)` returns
  `disk_format=FAT12` whenever `bios_drive_type` starts with
  `martypc-xebec:`.  No effect on Phoenix / AMI presets.
- TUI: `bios-drive-type` `Select` change handler now calls
  `_apply_bios_drive_snap()` which mirrors the coercion.
- GUI: `combo_bios` now bound to a dedicated `_on_bios_drive_change`
  handler that runs the coercion through `_coerce()`.
- 6 new tests in `tests/test_martypc.py` covering the 4 Xebec slugs
  + Phoenix non-coercion + empty-slug no-op.

## Compatibility

No CLI behavior change.  CLI users were never affected because they
pass `--format` and `--bios-drive-type` together explicitly — the
existing validation correctly rejects undersized FAT16 requests
with the clear error message.
