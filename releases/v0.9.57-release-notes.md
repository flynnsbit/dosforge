# dosforge v0.9.57

## Highlights

- **IBM 8088 + PC-DOS 3.x (`--boot-mode ibm8088 --ibm-dos-version pcdos3`)
  now supports FAT16 partitions up to 32 MiB.**

  v0.9.56 enabled FAT16 for the standalone `pcdos3` + `compaq3` boot
  modes.  This release extends the same historical correction to the
  IBM 8088 builder's parallel DOS-version dropdown
  (`IBMDOSVersion.PCDOS3`), which until now was hard-capped at
  16 MiB FAT12-only.

  Build behaviors:

  - `dosforge create --boot-mode ibm8088 --ibm-dos-version pcdos3
    --format fat16 --size 32M --disk-controller ide`
    -> 31.99 MiB VHD, MBR partition type 0x04 (FAT16 <32MiB)
  - `dosforge create --boot-mode ibm8088 --ibm-dos-version pcdos3
    --format fat12 --size 16M --disk-controller mfm
    --bios-drive-type phoenix:1`
    -> 10.16 MiB VHD, MBR partition type 0x01 (FAT12)
  - `--size 64M` -> `IBM PC-DOS 3.x IBM 8088/V20 profile images must
    not exceed 32 MiB.`

## Linux parity (no separate work needed)

v0.9.56 + v0.9.57 changes live entirely in cross-platform Python
modules (`models.py`, `size.py`, `formlogic.py`, `disk.py`).  The
Linux pip install and the Windows PyInstaller bundle import the
same source tree -- pushing the `v0.9.57` tag covers both
platforms.  No Linux-specific install path bypasses these caps:

- `_platform/linux.py` `_LEGACY_DOS_QEMU_BOOT_MODES` only enumerates
  `{COMPAQ331, MSDOS33, MSDOS331}`.  PCDOS3 and COMPAQ3 are NOT in
  that set; they use pre-extracted `dosassets/pcdos3/` system files
  via the standard `_uses_msdos33_filesystem_layout` flow.
- The Linux VHD path (qemu-nbd attach + parted + mkfs.fat -F 16 +
  boot install) is the same one MSDOS33 + FAT16 already exercises
  on Linux today.

## Code changes

- **`models.py`** — added `IBMDOSVersion.max_size_bytes_for_format(disk_format)`.
  `PCDOS3` returns 16 MiB for FAT12, 32 MiB for FAT16.  The legacy
  `max_size_bytes` property still returns the FAT12 cap (16 MiB)
  for back-compat.
- **`size.py`** — `validate_size_for_ibm_dos` now accepts an optional
  `disk_format` argument and uses the format-aware cap.  Improved
  error message for FAT12-over-cap suggesting FAT16 instead.
- **`disk.py`** — `_effective_size_cap_bytes`, the validation gate at
  `_validate_create_request`, the BIOS-preset re-validation, and
  `_normalize_vhd_size_for_chs` all switched to
  `max_size_bytes_for_format`.
- **`formlogic.py`** —
  - `_state_aware_max_mb` uses the format-aware cap.
  - `apply_ibm_default_size` defaults to 32M when IBM 8088 + PCDOS3
    + FAT16.
  - `coerce_on_format_change` re-applies the IBM-8088 default size
    so flipping format FAT12 -> FAT16 on PCDOS3 jumps 15M -> 32M.

## Stale labels + comments fixed

- TUI dropdown (`app.py:147`): `"PC-DOS 3.x (max 16MB, FAT12)"` ->
  `"PC-DOS 3.x (max 32MB, FAT12/16)"`.
- GUI dropdown (`_gui/options.py:101`): same fix.
- `e2e_matrix.py`: moved `BootMode.PCDOS3` + `BootMode.COMPAQ3` from
  `_FAT12_ONLY_NO_VHD` (now COMPAQ2-only) to `_LEGACY_FAT16_ONLY`,
  so the e2e matrix now generates FAT16 VHD test cases for both.

## Tests

- `tests/test_size_cap_snap.py` adds 4 new tests covering
  `IBMDOSVersion.PCDOS3` FAT12 (16 MiB) and FAT16 (32 MiB) caps
  plus the legacy `max_size_bytes` back-compat behavior.
- `tests/test_formlogic.py` adds
  `test_coerce_ibm8088_pcdos3_format_flip_to_fat16_bumps_to_32m`
  asserting that flipping format on the IBM 8088 form re-defaults
  the size from 15M to 32M.
- 84 unit tests pass (cap snap + formlogic + size + disk validation).

## Verified end-to-end on Windows

- `ibm8088 + pcdos3 + FAT16 + 32M + IDE` -> 33,546,752-byte VHD,
  MBR type 0x04 (FAT16 <32MiB).
- `ibm8088 + pcdos3 + FAT12 + 16M + MFM phoenix:1` -> 10.16 MiB VHD,
  MBR type 0x01 (FAT12) -- preset wins.
- `ibm8088 + pcdos3 + FAT16 + 16M + IDE` -> boundary case OK.
- `ibm8088 + pcdos3 + FAT16 + 64M` -> ValidationError with new
  guidance.
- `ibm8088 + pcdos3 + FAT12 + 32M + XT-IDE` -> cap-aware
  snap-down to 15.54 MiB (v0.9.54 behavior preserved).
