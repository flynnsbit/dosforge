# dosforge v0.4.0-osr2-authentic-pre1 — OSR2 boot authenticity

This pre-release closes the last authenticity gap for MS-DOS 7.1
(Win95 OSR2) boot images. Every file IO.SYS expects at `C:\` root
during the **"Starting Windows 95..."** phase is now sourced
byte-for-byte from the user's authentic OSR2 install media — no
synthesis, no cross-DOS borrowing, no stubs.

## What's fixed

### `C:\HIMEM.SYS` now staged for all install profiles (`81a2898`)

OSR2's IO.SYS implicitly loads `C:\HIMEM.SYS` as part of its
built-in defaults. Before this release, HIMEM staging only ran for
the **FULL** install profile, leaving the **MINIMAL/base** tier
booting with the cosmetic warning:

```
The following file is missing or corrupted: C:\HIMEM.SYS
```

HIMEM extraction was split out into a new
`_stage_msdos71_osr2_boot_essentials()` helper that runs for every
MSDOS71 profile. The DOS-tools staging (`C:\DOS\` from `ebd.cab`)
stays gated behind FULL. CONFIG.SYS / AUTOEXEC.BAT are always
written when HIMEM lands; PATH drops the `C:\DOS` segment for the
minimal tier.

### `C:\IFSHLP.SYS` + `C:\DBLBUFF.SYS` extracted host-side via 7-Zip (`8572a31`)

These two drivers live inside Quantum-compressed cabinets on the
OSR2 install media:

- `WIN95_13.CAB` (on `Disk13.img`) → `DBLBUFF.SYS` (2,100 B)
- `WIN95_17.CAB` (on `Disk17.img`) → `IFSHLP.SYS` (3,708 B)

The Diamond EXTRACT.EXE 1.00.0530 (04/3/95) that ships on the OSR2
Boot.img **predates Quantum support** — it fails with `Out of memory
while processing cabinet file` regardless of XMS budget. Microsoft's
`expand.exe` also refuses Quantum with error `0x80070032`.

We pivoted to **host-side extraction via 7-Zip**, which is
Quantum-capable and widely available. The real bytes get staged onto
`C:\` via `vhd_pre_install_copies` before the QEMU SYS install runs,
and the in-DOS AUTOEXEC.BAT just sets `+R +S +H` attributes.

7-Zip is probed via `PATH` + `Program Files\7-Zip\7z.exe`. If
absent, the VHD still builds and you'll just see the cosmetic boot
warning — no functional impact. Extracted files are cached
content-addressed under `%LOCALAPPDATA%\dosforge\cache\osr2-win95-files\<sha12>\`.

|---|---:|---|
| `HIMEM.SYS` | 33,191 B | (Boot.img verbatim) |
| `IFSHLP.SYS` | 3,708 B | `3272ceb4eb7f5e3fb6e87ad6f0130d3710ebc300890114cb592c770777e89476` |
| `DBLBUFF.SYS` | 2,100 B | `a929264b6ca7900fab45be16daf8ca44f757304c6f0fdcc076f8bfd4b88bfc28` |

All three carry `A SHR` (archive / system / hidden / read-only)
attributes to match what a real Win95 SETUP writes.

## What's verified

86Box boot-tested on Pentium-class BIOS for all 3 OSR2 install tiers:

| VHD | Tier | What's on C:\ |
|---|---|---|
| `ms-dos-710-osr2-vhd.vhd` (32 MB) | MINIMAL | IO.SYS, MSDOS.SYS, COMMAND.COM, HIMEM.SYS, IFSHLP.SYS, DBLBUFF.SYS, CONFIG.SYS, AUTOEXEC.BAT |
| `ms-dos-710-osr2-full-vhd.vhd` (32 MB) | FULL | Same + 26 files in `C:\DOS\` (FDISK, EXTRACT, FORMAT, EDIT, SCANDISK, etc.) |
| `ms-dos-710-osr2-hydrated-vhd.vhd` (131 MB) | FULL + custom payload | Same + your `--custom-payload-path` directory hydrated at root |

Boot warnings now silent on all 3 tiers. Boot drops straight to
`C:\>` prompt.

## How to test the OSR2 fixes

Rebuild any OSR2 tier from your local checkout against
`dosassets/w95/Boot.img` + the 22 Win95 floppy disk images:

```powershell
# MINIMAL — boot-only
dosforge create --path osr2-base.vhd --media-type vhd `
  --format fat16 --boot-mode msdos71 --size 32M --label DOSFORGE `
  --boot-assets-path dosassets\w95

# FULL — adds C:\DOS\ utilities
dosforge create --path osr2-full.vhd --media-type vhd `
  --format fat16 --boot-mode msdos71 --size 32M `
  --dos-install-profile full --label DOSFORGE `
  --boot-assets-path dosassets\w95

# FULL + custom payload
dosforge create --path osr2-hydrated.vhd --media-type vhd `
  --format fat16 --boot-mode msdos71 `
  --dos-install-profile full --custom-payload-path .\stage `
  --label DOSFORGE --boot-assets-path dosassets\w95
```

Boot any of these in 86Box on a **Pentium-class BIOS** — the
pre-EBIOS 486 BIOSes cannot boot OSR2 in general and are not a
target.

## Compatibility / dependencies

- **Optional**: 7-Zip installed on the host (`C:\Program Files\7-Zip\7z.exe`
  or on `PATH`) — required for the IFSHLP / DBLBUFF authentic files.
  Without it, the VHD still builds but the two cosmetic boot warnings
  return. Install via `winget install 7zip.7zip`.
- **Required**: as before — `mtools`, `qemu-img`, `dosbox-x` (all
  bundled in the full/lite Windows release zips).

## Known limitations (unchanged from `pre2`)

- No Windows 95 GUI boot path; `BootGUI=0` hard-coded in the OSR2
  `MSDOS.SYS` template. GUI boot would require shipping a full
  Setup-extracted Windows tree (separate asset + licensing story).
- Pre-EBIOS 486 BIOSes cannot boot OSR2; use a Pentium-class BIOS in
  86Box.
