# dosforge v0.8.5

UX cleanup + a pre-existing-regression mop-up.

## 1. Hide the generic "IBM PC-DOS (user-supplied install media)" from the dropdown

The generic `--boot-mode pcdos` was a confusing dropdown entry:
- It claimed "user-supplied install media" but only accepted IBM
  PC-DOS media (uses the `IBMBIO.COM` marker, not MS-DOS's `IO.SYS`).
- It was redundant with the 4 version-specific PC-DOS modes
  (`pcdos3`, `pcdos7`, `pcdos2000`, `pcdos71`) which all carry
  proper per-version size caps + asset layout docs.
- It had no version-aware size cap (PC-DOS 3.x = 32 MiB,
  5.x = 504 MiB, 6.x = 2 GiB), no BPB OEM check, and no asset
  readme for the user to know what to drop in `dosassets/pcdos/`.
- The "fallback to PC-DOS 7.0 LOADDSKF" branch was pure overlap
  with `--boot-mode pcdos7`.

Removed from both the TUI Step 1 dropdown and the GUI Boot OS
combo. **CLI compatibility preserved** — `--boot-mode pcdos` is
still accepted and works as before for advanced users with raw
PC-DOS 3.10 / 3.20 / 3.30 / 4.00 / 5.00 / 6.x install IMGs.
Added `dosassets/pcdos/readme.txt` documenting the CLI-only path,
expected media layout, and pointers to the version-specific
modes that cover the popular releases.

## 2. Add missing DosProfile entries for 7 boot modes

`tests/test_dos_profiles.py::test_every_bootmode_enum_value_has_a_profile_or_is_none`
has been failing since v0.7.11 (when `msdos6` / `compaq3` /
`drdos6` / `drdos7` landed without per-mode DosProfile registrations
in `src/dosforge/_dos/`) and was independently missing entries for
`compaq2` / `pcdos3` / `pcdos2000` from earlier releases too.

Added all 7 missing profiles (`msdos6`, `compaq2`, `compaq3`,
`pcdos3`, `pcdos2000`, `drdos6`, `drdos7`) with the correct per-mode
metadata (BPB OEM stamp, system file names, FAT support, pre-DOS-5
flag).  Registered each in `_dos/__init__.py`'s `_PROFILES` table.

## Tests

All previously-passing focused tests still pass + 1 newly-passing
test (`test_every_bootmode_enum_value_has_a_profile_or_is_none`).
