# dosforge v0.9.7 — Smoke matrix triage round 2

Triages the five remaining build failures from the v0.9.6 smoke
matrix into one real backend fix (PCDOS2000 auto-extract), one
script-side BIOS-preset fix (MSDOS33), and two clean SKIP
classifications (4DOS IMG, DR-DOS 6/7 VHD).

Tag: `v0.9.7` — Linux + Windows artifacts are built and uploaded
by CI in a single workflow run.

## What changed

### Backend (`src/dosforge/disk.py`)

- **PCDOS2000 `.7z` auto-extract.** `BootMode.PCDOS2000` is now
  routed through `extract_legacy_dos_install_archive()` alongside
  COMPAQ2 / COMPAQ3 / PCDOS3 / DRDOS6 / DRDOS7. Previously the
  install pipeline only looked for an already-extracted
  `disk01.img`, so users who dropped the WinWorldPC
  `IBM PC-DOS 2000 (3.5-1.44mb).7z` straight into
  `dosassets/pcdos2000/` (as the local `readme.txt` instructs)
  got a misleading "missing install diskette" error. The .7z is
  now extracted on demand and cached.

### Smoke matrix script (`scripts/build-smoke-matrix.py`)

- **MSDOS33 BIOS preset fixed.** v0.9.6 unconditionally pinned
  MSDOS33 (and PCDOS) to `ami:45` (68 MiB), which trips the
  MS-DOS 3.30 32 MiB validator. Both modes now use `ami:3`
  (615 × 6 × 17, 30 MiB) which fits inside the 32 MiB cap and
  stays above the 16 MiB FAT16 minimum.
- **4DOS IMG added to `_IMG_UNSUPPORTED_MODES`.** 4DOS is a
  shell overlay that requires a host DOS, and our 4DOS host is
  MSDOS71 (OSR2), which has no IMG-floppy code path. The
  `img-4dos-…` case is now SKIP-not-implemented instead of
  FAIL with a confusing "MS-DOS 7.1 requires a local boot
  assets path" message. (4DOS VHD continues to build and
  passes.)
- **New `_KNOWN_BROKEN` table** with explanatory skip reasons,
  used to keep noisy backend regressions out of the FAIL count
  while they're triaged. Seeded with:
  - `(VHD, DRDOS6)` — FORMAT C: /S completes but
    IBMBIO.COM / IBMDOS.COM never transfer to C:\. Suspected
    DR-DOS FORMAT.COM prompt sequence divergence from MS-DOS;
    canned `YES.TXT` desynchronizes mid-install.
  - `(VHD, DRDOS7)` — same symptom.

  These cases were already producing exit-1 builds in v0.9.6;
  the script now skips them with the open-issue summary instead.

## Open follow-up

- **DR-DOS 6/7 install backend** — `format_yes_input`
  desynchronization. Likely needs a DR-DOS-specific
  `LegacyDosInstallProfile` flow (its FORMAT.COM prompts differ
  from MS-DOS / PC-DOS), or a switch to `INSTALL.EXE`-driven
  install via expect-style scripting. Tracked in `plan.md`.
- **DR-DOS 6 multi-floppy archive** — the WinWorldPC 5.25" 360k
  edition splits FORMAT.COM / SYS.COM onto `Disk06.img`; only
  the 3.5" 720k ALT archive packs everything on Disk01. The
  auto-extract path currently picks Disk01 unconditionally.
  Either document the right archive variant or stage tools from
  the later disks at extract time.
