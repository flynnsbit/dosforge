# dosforge v0.5.0-gui-pre3 — CLI-only `dosforge.exe`, GUI moves to `dosforge-gui.exe`

The Windows bundles now ship two cleanly separated launchers:

- **`dosforge.exe`** — pure command-line. No TUI, no GUI. Run it with no
  arguments to see the full help including ready-to-copy examples for
  building VHDs and floppies.
- **`dosforge-gui.exe`** — windowed (no console flash) GUI launcher.
  No TUI fallback: if the GUI can't start, the launcher exits with an
  error instead of falling back to a console TUI.

Both launchers share one `_internal/` Python runtime and dispatch from
a single entry script based on the EXE's filename.

## What changed

- New `dosforge.cli.cli_only_main()` and `dosforge.cli.gui_only_main()`
  functions.
- `dosforge.exe` no longer exposes `tui` or `gui` subcommands. Use
  `dosforge-gui.exe` for the GUI; pip-installed `dosforge` (Linux/dev)
  still supports both.
- The `--help` output now includes example commands for: bootable
  MS-DOS 6.22 VHD, IBM PC 8088 DOS 3.3 VHD with custom payload,
  bootable MS-DOS 3.3 floppy, 720K data floppy, FAT32 MS-DOS 7.1 VHD,
  and a dependency-preflight invocation.
- Windows specs drop the textual / rich / pygments TUI stack
  entirely from the bundle — neither launcher loads it.

## Notes on bundle size

The full and lite bundles still contain the GUI runtime (tkinter +
sv_ttk) because `dosforge-gui.exe` needs it. The CLI-only standalone
bundle (`dosforge-0.5.0-gui-pre3-cli-windows-x64.zip`) remains the
minimal option for users who only need the CLI verbs.

Dropping the textual stack saves roughly 15–20 MB from the full/lite
bundles versus pre2.
